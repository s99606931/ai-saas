> **CSAP**: D-10(부하분산), D-06(침해사고 관리), D-12(시스템 개발 보안)
> **버전**: 1.0.0 | **최종 갱신**: 2026-04-10

## 1. 개요

본 문서는 공공기관 SaaS 플랫폼의 자동 롤백 정책을 정의합니다.
모든 서비스 배포는 Argo Rollouts의 AnalysisRun을 통해 자동 검증되며,
메트릭 임계값 위반 시 수동 개입 없이 이전 안정 버전으로 자동 롤백됩니다.

## 2. 티어별 롤백 기준

### 2.1 Critical 티어 (api-gateway, auth-service, audit-service)

| 메트릭 | 임계값 | 평가 | 비고 |
|--------|--------|------|------|
| 에러율 (5xx) | > 0.5% | 30초 간격 x 10회, 2회 실패 시 롤백 | 최소 허용 |
| P95 지연시간 | > 기준값 x 2 | 30초 간격 x 10회, 2회 실패 시 롤백 | 기준값: SLO 정의 참조 |
| 가용성 | < 99.9% | 60초 간격 x 5회, 2회 실패 시 롤백 | SLO 연동 |
| 롤백 대기 | 즉시 | - | 대기 없이 즉시 실행 |

### 2.2 High 티어 (tenant-service, user-service, subscription-service, ai-gateway)

| 메트릭 | 임계값 | 평가 | 비고 |
|--------|--------|------|------|
| 에러율 (5xx) | > 1.0% | 30초 간격 x 10회, 3회 실패 시 롤백 | 표준 허용 |
| P95 지연시간 | > 기준값 x 2 | 30초 간격 x 10회, 3회 실패 시 롤백 | |
| 가용성 | < 99.5% | 60초 간격 x 5회, 2회 실패 시 롤백 | |
| 롤백 대기 | 30초 | - | 일시적 스파이크 필터 |

### 2.3 Standard 티어 (나머지 서비스)

| 메트릭 | 임계값 | 평가 | 비고 |
|--------|--------|------|------|
| 에러율 (5xx) | > 2.0% | 60초 간격 x 5회, 3회 실패 시 롤백 | 관대 허용 |
| P95 지연시간 | > 기준값 x 3 | 60초 간격 x 5회, 3회 실패 시 롤백 | |
| 가용성 | < 99.0% | 60초 간격 x 5회, 3회 실패 시 롤백 | |
| 롤백 대기 | 60초 | - | |

## 3. 배포 후 자동 검증 흐름

```
1. 배포 시작 → Canary Pod 생성 (5% 트래픽)
2. AnalysisRun 시작 (해당 티어 AnalysisTemplate)
3. 5분 관찰 기간 (에러율 + 지연 + 가용성 동시 검증)
4-A. 통과 → 트래픽 점진 증가 (25% → 50% → 100%)
4-B. 실패 → 즉시 abort → 트래픽 100% stable 복원
5. 롤백 알림 발송 + 이력 기록
```

## 4. 롤백 발생 시 후속 조치

| 티어 | 알림 대상 | 후속 조치 | 시한 |
|------|----------|----------|------|
| Critical | SRE + 서비스 오너 + 경영진 | 즉시 포스트모템 작성 | 2시간 이내 |
| High | SRE + 서비스 오너 | 원인 분석 + 수정 | 24시간 이내 |
| Standard | SRE 팀 | 주간 리뷰 시 분석 | 1주일 이내 |

## 5. 정책 변경 절차

1. SRE 팀이 변경 제안서 작성 (사유 + 영향 분석)
2. 해당 서비스 오너 합의
3. PM 승인
4. 이 문서 + AnalysisTemplate 동시 업데이트
5. 변경 이력에 기록
