# Kyverno - OPA Gatekeeper 역할 분리 정책

> **버전**: 1.0.0 | **작성일**: 2026-04-10
> **Design Ref**: MTU-N53 Section 3.1
> **Plan SC**: FR-N53.3

---

## 1. 개요

공공기관 SaaS 프레임워크는 이중 정책 엔진 구조를 채택합니다.
각 엔진이 최적화된 영역을 전담하여 CSAP 79개 통제항목 커버리지를 극대화합니다.

---

## 2. 역할 분리 매트릭스

| 정책 영역 | Kyverno (v1.17) | OPA Gatekeeper (v3.18) | 근거 |
|----------|-----------------|----------------------|------|
| 이미지 서명 검증 (Cosign) | **담당** | - | Cosign 네이티브 통합 |
| SLSA Provenance 검증 | **담당** | - | 이미지 메타데이터 접근 |
| 라벨/어노테이션 Mutation | **담당** | - | mutate 지원 |
| 특권 컨테이너 차단 | - | **담당** | Rego 기반 조건 처리 |
| 리소스 제한 강제 | - | **담당** | Rego 기반 조건 처리 |
| 허용 레지스트리 제한 | - | **담당** | 파라미터화된 정책 |
| hostPath/Network 차단 | - | **담당** | Pod Spec 심층 검사 |
| latest 태그 차단 | - | **담당** | 이미지 문자열 분석 |
| 비루트 실행 강제 | - | **담당** | securityContext 분석 |
| 읽기 전용 FS 강제 | - | **담당** | securityContext 분석 |

---

## 3. 충돌 방지 규칙

1. **중복 정책 금지**: 동일 리소스에 양 엔진이 동일 검사를 수행하지 않음
2. **네임스페이스 예외 동기화**: 양 엔진의 제외 네임스페이스 목록을 동일하게 유지
3. **Webhook 순서**: Kyverno(mutating) -> Gatekeeper(validating) 순서 보장
4. **리포팅 통합**: Policy Reporter(Kyverno) + Gatekeeper Metrics -> 동일 Grafana

## 4. CSAP 매핑

| CSAP 통제항목 | Kyverno 정책 수 | Gatekeeper 정책 수 | 합계 |
|-------------|----------------|-------------------|------|
| D-08 접근통제 | 2 (라벨 강제) | 5 (특권, hostPath, hostNetwork, nonroot, readonlyFS) | 7 |
| D-09 암호화 | 1 (이미지 서명) | 1 (허용 레지스트리) | 2 |
| D-12 개발보안 | 1 (Provenance) | 2 (리소스 제한, latest 차단) | 3 |
| **합계** | **4** | **8** | **12** |

## 5. 운영 절차

### 정책 추가 시
1. 해당 영역의 담당 엔진 확인 (이 문서 참조)
2. 설계 문서에 CSAP 매핑 명시
3. GitOps 리포지토리에 커밋 (Flux 자동 배포)
4. 양성/음성 테스트 케이스 작성 후 검증

### 정책 변경 시
1. 변경 사유 및 CSAP 영향도 문서화
2. `dryrun` 모드로 사전 테스트
3. 검증 완료 후 `deny` 모드 전환
