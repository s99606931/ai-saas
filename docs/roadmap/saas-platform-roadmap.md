## Executive Summary

| 관점 | 내용 |
|------|------|
| **기존 완료** | 35개 MTU 문서 프레임워크 — CSAP/N2SF/ISMS-P 가이드, 감리 템플릿, 인프라 레시피, AI 연동 패턴 |

## 2. 신규 Phase 구성 (Phase P1 ~ P6)

> 기존 35 MTU (문서 프레임워크)는 **완료** 상태. 아래 Phase는 **플랫폼 구현체** 개발 로드맵.

### Phase P1: 플랫폼 기반 서비스 (M1~M3)

| MTU ID | 서비스명 | 주요 기능 | 의존성 | 복잡도 |
|--------|---------|---------|--------|--------|
| MTU-P01 | **인증 서비스** | JWT 발급/검증, RBAC, 멀티테넌트 세션, OAuth2/OIDC | 없음 | HIGH |
| MTU-P02 | **사용자 관리 서비스** | 사용자 CRUD, 역할 할당, 비밀번호 정책, MFA | MTU-P01 | HIGH |
| MTU-P03 | **테넌트 관리 서비스** | 테넌트 생성/삭제, 테넌트 격리, 설정 관리 | MTU-P01, P02 | HIGH |
| MTU-P04 | **API 게이트웨이** | 라우팅, 인증 미들웨어, Rate Limiting, 플러그인 등록 | MTU-P01 | HIGH |

**Phase P1 완료 기준**: 테넌트 격리 + 인증 + API 게이트웨이로 비즈니스 마이크로서비스 연결 가능

---

### Phase P2: 핵심 SaaS 서비스 (M3~M5)

| MTU ID | 서비스명 | 주요 기능 | 의존성 | 복잡도 |
|--------|---------|---------|--------|--------|
| MTU-P05 | **메뉴 관리 서비스** | 동적 메뉴 구성, 역할별 메뉴 권한, 드래그앤드롭 편집 | MTU-P01~P03 | MED |
| MTU-P06 | **SaaS 서비스 카탈로그** | 서비스 등록, 버전 관리, 기능 토글(Feature Flag) | MTU-P03 | MED |
| MTU-P07 | **구독 관리 서비스** | 플랜 정의, 테넌트별 구독, 사용량 추적, 업그레이드/다운그레이드 | MTU-P03, P06 | HIGH |
| MTU-P08 | **빌링 서비스** | 청구 주기, 인보이스 생성, 결제 이력 (공공: 세금계산서 연동) | MTU-P07 | HIGH |

**Phase P2 완료 기준**: 테넌트 고객이 서비스를 구독하고 구독 상태에 따라 기능 접근 가능

---

### Phase P3: 비즈니스 지원 서비스 (M5~M7)

| MTU ID | 서비스명 | 주요 기능 | 의존성 | 복잡도 |
|--------|---------|---------|--------|--------|
| MTU-P09 | **CRM 서비스** | 고객사 관리, 담당자 관리, 계약 관리, 파이프라인 | MTU-P02, P03 | HIGH |
| MTU-P10 | **AI 서비스 관리** | AI 모델 등록, N2SF 등급 게이트웨이, 사용량 모니터링, 비용 추적 | MTU-P01, P03 | HIGH |
| MTU-P11 | **알림 서비스** | 이메일/SMS/인앱 알림, 알림 템플릿, 구독 이벤트 트리거 | MTU-P02, P03 | MED |
| MTU-P12 | **파일 관리 서비스** | 파일 업로드/다운로드, AES-256 암호화, 접근 제어, 바이러스 스캔 | MTU-P01 | MED |

**Phase P3 완료 기준**: 비즈니스 로직 마이크로서비스가 공통 서비스(CRM, AI, 알림, 파일)를 재사용 가능

---

### Phase P4: 감사 & 준수 서비스 (M7~M8)

| MTU ID | 서비스명 | 주요 기능 | 의존성 | 복잡도 |
|--------|---------|---------|--------|--------|
| MTU-P13 | **감사 로그 서비스** | append-only 로그, 1년 보존, 무결성 검증, CSAP D-06 자동 준수 | MTU-P01~P03 | HIGH |
| MTU-P14 | **준수 현황 대시보드** | CSAP 79항목 실시간 준수율, N2SF 6영역 현황, 감리 준비도 점수 | MTU-P13 | MED |
| MTU-P15 | **보안 모니터링** | 이상 접근 탐지, 로그인 실패 알림, IP 차단, 세션 이상 탐지 | MTU-P01, P13 | MED |

**Phase P4 완료 기준**: CSAP D-06/D-08 자동 준수 + 감리관이 대시보드에서 준수율 확인 가능

### Phase P5: 관리자 포털 & 비즈니스 플러그인 SDK (M8~M10)

| MTU ID | 서비스명 | 주요 기능 | 의존성 | 복잡도 |
|--------|---------|---------|--------|--------|
| MTU-P16 | **관리자 포털 (Next.js 15)** | 역할별 대시보드, 테넌트 관리, 전체 서비스 통합 UI | MTU-P01~P15 | HIGH |
| MTU-P17 | **테넌트 포털 (Next.js 15)** | 테넌트 셀프서비스, 구독 관리, 비즈니스 서비스 실행 | MTU-P05~P08 | HIGH |
| MTU-P18 | **비즈니스 플러그인 SDK** | 마이크로서비스 등록 API, CSAP 준수 체크 훅, 감리 산출물 자동 생성 | MTU-P04 | HIGH |

**Phase P5 완료 기준**: 포털에서 전체 서비스 운영 가능 + SDK로 비즈니스 마이크로서비스 플러그인 가능

### Phase P6: 포크 가이드 & 하네스 최적화 (M10~M12)

| MTU-P21 | **통합 테스트 & 성능 검증** | 멀티테넌트 부하 테스트, CSAP 전항목 자동 검증, 감리 모의 통과 | 전체 | HIGH |

## 4. 기술 스택 (Platform Layer)

| 계층 | 기술 | 근거 |
|------|------|------|
| **프론트엔드** | Next.js 15 + React 19 + Tailwind v4 + shadcn/ui | MTU-U1 설계 확정 |
| **API 게이트웨이** | Fastify 5 + @fastify/auth + Zod | 고성능, TypeScript 네이티브 |
| **마이크로서비스** | Node.js 22 (Fastify) 또는 Go 1.22 | 서비스별 선택 |
| **데이터베이스** | PostgreSQL 16 + Prisma 6 | CSAP D-09 암호화 내장 |
| **메시지 브로커** | Redis 7 (Pub/Sub) + BullMQ | 알림, 이벤트 드리븐 |
| **파일 스토리지** | MinIO (S3 호환, 폐쇄망) | 외부 클라우드 금지 |
| **인증** | JWT (RS256) + NextAuth.js v5 | CSAP D-08 세션 15분 |
| **서비스 메시** | k3s 내부 DNS + Kubernetes Service | MTU-I1 기반 |
| **모니터링** | OpenTelemetry + Prometheus + Grafana + Loki | MTU-I4 기반 |
| **CI/CD** | Gitea + Gitea Actions + Flux GitOps + Harbor | MTU-I2, I3 기반 |

## 5. CSAP/감리 자동 준수 체계 (신규 MTU와 연계)

| CSAP 항목 | 자동 준수 서비스 | 구현 MTU |
|---------|-------------|---------|
| D-08 접근 통제 | 인증 서비스 (JWT RBAC) + API 게이트웨이 | MTU-P01, P04 |
| D-06 침해사고 관리 | 감사 로그 서비스 (append-only) | MTU-P13 |
| D-09 암호화 | 파일 서비스 (AES-256) + DB 암호화 | MTU-P12 |
| D-12 시스템 개발 보안 | 하네스 엔지니어링 (AgentShield 102규칙) | MTU-P20 |
| D-05 공급망 보안 | Harbor + Sigstore + SBOM | MTU-I3 (기존) |

## 6. 포크 시나리오 (How to Use)

```
Step 1: 레포 포크
  git clone public-saas-framework
  git remote add origin my-business-repo

Step 2: 환경 설정
  cp .env.example .env.local
  # 비즈니스명, 도메인, DB 설정 변경

Step 3: 비즈니스 마이크로서비스 개발
  cd business-template/my-business-service
  # CSAP 준수 가이드 따라 비즈니스 로직 구현
  # AI 코드 생성 시 하네스가 자동으로 CSAP 체크

Step 4: 플랫폼에 서비스 등록
  # API 게이트웨이에 서비스 등록
  # 관리자 포털에서 메뉴 구성
  # 구독 플랜에 서비스 연결

Step 5: 배포
  git push → Gitea Actions → Harbor → Flux → k3s
  # 감리 산출물 자동 생성됨
```
