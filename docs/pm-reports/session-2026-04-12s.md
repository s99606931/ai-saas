## Key Decisions & Outcomes

### 1) R155 모듈명 충돌 회피
`context-window-manager.ts`(R21, 322줄)가 이미 존재하여 R155를 `context-budget-optimizer.ts`로 **역할 분리 명명**. R21은 "단일 컨텍스트의 system/context/conversation/generation 토큰 예산 영역 관리", R155는 "다수 후보 조각 중 예산 내 선택(knapsack)" — 단일 책임 원칙 준수. Plan/Design 문서 서두에 분리 근거 명시.

### 2) R153 압축 알고리즘 2단계 설계
budget 초과 시 (1) 연속 일반 턴 2개 이상 → `[SUMMARY: n turns, topics=...]` 단일 system 턴 치환, (2) 여전히 초과 시 summary 먼저 제거 후 가장 오래된 일반 턴 FIFO 삭제. **pinned 턴은 모든 단계에서 보존**, keepRecent(기본 2) 최근 턴 보존. 테스트 1건 실패 후 "최근 턴 보존 집합 계산 → victim 선택" 로직으로 보정.

### 3) R154 점수 모델
`categories.length × 0.25` → 임계값 0.25 warn / 0.5 block. 단일 시그니처는 warn, 2개 이상은 block — 오탐 최소화 + 명백한 다중 공격 즉시 차단.

### 4) R156 단일 샘플 baseline
샘플 1개일 때 pairwise 계산 불가 → **score=1**로 설정(일관성 측정 최소 샘플 수 부족 = 실패가 아닌 정보 부족). QA 워크플로우에서 초기 상태 혼동 방지.

### 5) R157 필수 섹션 8개
`missing_field:<field>` 구조화 오류로 필드 단위 식별 + `validateChecklist()` 체크리스트 검증 — 감리 대응 시 개별 섹션 완비 여부 즉시 확인 가능.
