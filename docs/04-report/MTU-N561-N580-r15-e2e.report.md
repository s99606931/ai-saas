## 2. Key Decisions & Outcomes

### 결정 1: Vitest 정적 검증 패턴 채택 (Design 옵션 B)
- **WHY**: 기존 7개 시나리오와 일관성, CI 안정성, 기동 비용 0
- **결과**: 5개 파일 모두 30초 이내 실행, 555ms 평균

### 결정 2: 패턴 매칭 완화 (구현 중 발견)
- **이슈**: 초기 작성 시 한국어 주석/대소문자 차이로 7개 실패
- **해결**: 타입명/클래스명 기준 매칭으로 변경 (`Satisfaction`, `OnboardingSurvey`, `MarketAgent`, `AgentAuditEntry`)
- **교훈**: E2E 정적 검증은 export 식별자(타입/함수명) 기반이 안정적

### 결정 3: 다양한 구현 패턴 OR 매칭
- audit/grade 등 SDK 위임형 모듈은 SDK import 또는 함수명 OR 매칭
- 예: `audit-sdk` || `createServiceAuditLogger` || `logAiEvent`
