# CI/CD 파이프라인 최적화 가이드

> **버전**: 1.0.0 | **작성일**: 2026-04-09
> **Design Ref**: MTU-N51 Design

---

## 개요

이 가이드는 Gitea Actions 기반 CI/CD 파이프라인 최적화 전략을 설명합니다.
Matrix strategy + 증분 빌드 + 캐싱을 통해 파이프라인 소요 시간을 최소화합니다.

---

## 최적화 전략

### 1. Matrix Build (병렬 빌드)

| 전략 | 설명 | 효과 |
|------|------|------|
| 서비스별 병렬화 | 각 서비스를 독립 Job으로 분리 | 직렬 대비 60~80% 시간 절감 |
| max-parallel: 4 | 동시 실행 Job 제한 | 러너 리소스 보호 |
| fail-fast: false | 한 서비스 실패 시 다른 서비스 계속 | 전체 결과 확인 가능 |

### 2. 증분 빌드 (변경 서비스만)

```bash
# git diff 기반 변경 탐지
git diff --name-only $BASE_SHA HEAD | grep '^services/' | cut -d'/' -f2

# 예외: packages/ 변경 → 전체 빌드
# 예외: docker/ 변경 → 전체 빌드
```

### 3. Docker 캐시 최적화

| 계층 | 캐시 전략 | 효과 |
|------|---------|------|
| 의존성 (Stage 1) | pnpm-lock.yaml 해시 키 | 의존성 미변경 시 스킵 |
| 빌드 (Stage 2) | 소스 변경만 재빌드 | 빠른 빌드 |
| 런타임 (Stage 3) | Alpine 기본 이미지 캐시 | 최소 이미지 |
| Buildx 캐시 | local type 캐시 | 레이어 재사용 |

### 4. 멀티스테이지 Dockerfile

```
Stage 1 (deps):     프로덕션 의존성만 설치 → 캐시
Stage 2 (build):    TypeScript 빌드
Stage 3 (runtime):  Alpine + 빌드 결과만 → 최소 이미지
```

**이미지 크기 비교**:
| 방식 | 이미지 크기 |
|------|-----------|
| 단일 스테이지 | ~800MB |
| 멀티스테이지 | ~150MB |
| 최적화 멀티스테이지 | ~80MB |

## 성능 벤치마크 목표

| 메트릭 | 목표 | 현재 |
|--------|------|------|
| 전체 빌드 (Cold) | < 10분 | 측정 필요 |
| 증분 빌드 (Cache) | < 3분 | 측정 필요 |
| 단일 서비스 빌드 | < 2분 | 측정 필요 |
| 이미지 크기 | < 100MB | 측정 필요 |
