# 인시던트 심각도/영향도 분류 체계

> Design Ref: MTU-N117 Design SS2.4
> Plan SC: FR-N117.5
> CSAP: D-06(침해사고 관리 -- 인시던트 분류)
> 작성일: 2026-04-10

---

## 1. 심각도 등급 정의

| 등급 | 명칭 | 정의 | 대응 시간 | 에스컬레이션 |
|------|------|------|----------|------------|
| P1 | 긴급 (Critical) | 전체 서비스 중단, 보안 침해, 데이터 손실 위험 | 즉시 | 15분 내 팀리더, 30분 내 CTO |
| P2 | 높음 (High) | 단일 서비스 장애, 성능 심각 저하, SLO 위반 | 5분 이내 | 30분 내 팀리더 |
| P3 | 보통 (Medium) | 부분 기능 장애, 성능 저하 (SLO 범위 내) | 30분 이내 | 2시간 내 팀리더 |
| P4 | 낮음 (Low) | 경미한 이상, 비 프로덕션 환경 이슈 | 2시간 이내 | 다음 업무일 |

## 2. 영향도 매트릭스

### 2.1 영향 범위별 분류

| 범위 | 설명 | 예시 |
|------|------|------|
| 전체 서비스 | 모든 테넌트/사용자 영향 | 클러스터 장애, 네트워크 단절, DNS 장애 |
| 단일 서비스 | 특정 서비스/테넌트 영향 | API 서버 OOM, DB 연결 풀 고갈 |
| 부분 기능 | 특정 기능만 영향 | 검색 기능 장애, 파일 업로드 실패 |
| 비프로덕션 | 개발/스테이징 환경만 영향 | CI/CD 파이프라인 실패, 테스트 환경 장애 |

### 2.2 카테고리-심각도 자동 매핑

| 카테고리 | 전체 서비스 | 단일 서비스 | 부분 기능 | 비프로덕션 |
|---------|-----------|-----------|---------|-----------|
| 보안 (Security) | P1 | P1 | P2 | P2 |
| 가용성 (Availability) | P1 | P2 | P3 | P4 |
| 성능 (Performance) | P2 | P3 | P3 | P4 |
| 인프라 (Infrastructure) | P1 | P2 | P3 | P4 |
| 배포 (Deployment) | P2 | P3 | P3 | P4 |
| 데이터 (Data) | P1 | P2 | P3 | P3 |

## 3. 알림 패턴별 자동 분류

| 알림 패턴 | 카테고리 | 기본 심각도 | 자동 조치 |
|----------|---------|-----------|----------|
| `Falco*`, `PolicyViolation*`, `Gatekeeper*`, `Kyverno*` | 보안 | P1 | 보안팀 즉시 알림 |
| `ServiceDown*`, `SLO*`, `ErrorBudget*` | 가용성 | P1 | SRE팀 알림 + 자동 롤백 후보 |
| `HighLatency*`, `Anomaly*`, `SlowQuery*` | 성능 | P2 | 개발팀 + SRE팀 알림 |
| `NodeDown*`, `NodeNotReady`, `DiskSpace*`, `OOM*` | 인프라 | P1~P2 | 인프라팀 알림 + 자동 런북 |
| `Flux*`, `Deployment*`, `Helm*` | 배포 | P2~P3 | DevOps팀 알림 |
| `PostgreSQL*`, `Database*` | 데이터 | P1~P2 | DBA팀 알림 |

## 4. 포스트모템 트리거 조건
