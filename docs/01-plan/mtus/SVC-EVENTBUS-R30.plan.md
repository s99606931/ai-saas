## Executive Summary

| 관점 | 내용 |
|------|------|
| 비즈니스 | 서비스 간 느슨한 결합, 이벤트 기반 워크플로우 |
| 기술 | In-process Pub/Sub, 타입 안전 이벤트, 와일드카드 구독, 비동기 핸들러 |
| 보안 | 이벤트 감사 추적, 테넌트 격리 이벤트 필터링 |
| 운영 | 핸들러 타임아웃, 에러 격리, 메트릭 (발행/구독 수) |

---

## Context Anchor

| 항목 | 내용 |
|------|------|
| WHY | 17개 마이크로서비스 간 이벤트 기반 통신 표준화 필요 |
| WHO | 서비스 개발자 (이벤트 발행/구독), SRE (이벤트 모니터링) |
| RISK | 직접 호출 방식의 강한 결합 → 장애 전파, 확장성 저하 |
| SUCCESS | 타입 안전한 이벤트 발행/구독, 에러 격리, 감사 추적 |
| SCOPE | In-process Event Bus (Phase 1). Redis Streams 연동은 Phase 2 |

## 기능 요구사항

| ID | 요구사항 | 우선순위 | 검증 방법 |
|----|---------|---------|----------|
| FR-EB.1 | 이벤트 발행 (emit) + 구독 (on/subscribe) | P0 | 단위 테스트 |
| FR-EB.2 | 와일드카드 패턴 구독 (예: user.*) | P1 | 단위 테스트 |
| FR-EB.3 | 일회성 구독 (once) | P1 | 단위 테스트 |
| FR-EB.4 | 구독 해제 (off/unsubscribe) | P0 | 단위 테스트 |
| FR-EB.5 | 비동기 핸들러 + 에러 격리 (한 핸들러 실패가 다른 핸들러에 영향 안됨) | P0 | 단위 테스트 |
| FR-EB.6 | 이벤트 메트릭 (발행/구독 수, 에러 수) | P1 | 단위 테스트 |
