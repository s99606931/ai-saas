## 목적

공공기관 SaaS 프레임워크를 장기 운영하면서 CSAP·N2SF·ISMS-P 등 규정 변경에 신속하게 대응하고,
기존 인증(CSAP·ISMS-P)에 영향 없이 안전하게 업그레이드하는 버전 관리 체계를 제공합니다.
MTU-A7(N2SF 모니터링)에서 탐지한 규정 변경을 30일 SLA 내에 프레임워크에 반영하는 파이프라인을 정의합니다.

---

## 시장조사 반영 / 선택 근거

| 근거 | 내용 |
|------|------|
| 규정 변경 빈도 | N2SF: 연 1~2회, CSAP: 1~3년 주기, ISMS-P: 1~2년 주기 → 지속적 프레임워크 갱신 필요 |
| 인증 영향 최소화 | CSAP 인증 유효기간(3년) 중 프레임워크 업그레이드가 기존 인증 무효화하면 안 됨 |
| 시맨틱 버저닝 | 규정 개정(MAJOR)·기능 추가(MINOR)·버그 수정(PATCH) 명확 구분 → 사용자 영향 사전 고지 |
| MTU-A7 연동 | N2SF 모니터링 프로세스와 30일 SLA 공유 → 단일 파이프라인으로 운영 효율화 |

## 핵심 설계 내용

### 1. 프레임워크 버전 체계 (시맨틱 버저닝)

```
vMAJOR.MINOR.PATCH

MAJOR: 규정 개정으로 하위 호환 불가한 변경
       예) CSAP 79항목 → 85항목 (기준 개정)
           N2SF 등급 체계 변경
           ISMS-P 의무화 신규 요건 추가
       → 기존 CSAP 인증 보유 기관: 재심사 필요 여부 사전 안내

MINOR: 신규 기능 추가, 하위 호환 유지
       예) 새 가이드 문서 추가, 새 MTU 추가
           선택적 보안 강화 기능 추가
       → 기존 인증에 영향 없음

PATCH: 오류 수정, 설명 보완, 오탈자 수정
       예) 체크리스트 오류 수정, 코드 예시 버그 수정
       → 기존 인증에 영향 없음
```

**버전 예시**:

| 버전 | 변경 내용 | 인증 영향 |
|------|---------|---------|
| v1.0.0 | 최초 릴리스 (28 MTU) | — |
| v1.1.0 | MTU 분할·신규 추가 (32 MTU) | 없음 |
| v1.2.0 | LM Studio 적용, 잔여 MTU Plan 완성 | 없음 |
| v2.0.0 | CSAP 기준 개정 반영 (가상) | MAJOR: 재검토 필요 |

### 2. 규정 변경 → 프레임워크 업데이트 파이프라인 (MTU-A7 연동)

```
[MTU-A7: 주간 모니터링]
  국정원 N2SF 공지 / KISA CSAP 공지 / 과기정통부 ISMS-P 공지
    │
    ▼
[변경 탐지] — Gitea Issue 자동 생성 (label: regulation-change)
    │
    ├── 영향 없음 → 로그 기록 후 종료
    │
    └── 영향 있음 → [영향 분석] (D+5)
            │
            ▼
        [업데이트 분류]
            ├── PATCH: 즉시 수정 → PR → Auditor 검증 → 병합
            ├── MINOR: 설계 → 구현 → Reviewer → Auditor → 병합
            └── MAJOR: CTO 승인 → 설계 → 구현 → 전체 Q-Gate → 병합
            │
            ▼
        [문서 업데이트 완료] (D+30 이내, NFR-7 연동)
            │
            ▼
        [Auditor 재검증 + CHANGELOG 업데이트]
            │
            ▼
        [사용 중 기관 알림 발송] (MAJOR인 경우 재심사 안내 포함)
```

### 3. 기존 인증 영향 없이 업그레이드 설계 원칙

| 원칙 | 설명 |
|------|------|
| 불변 증적 보존 | 기존 `audit.jsonl` 및 CSAP 증적 파일 수정 금지. 신규 버전은 별도 경로에 추가 |
| 버전 격리 문서 | 각 MTU 산출물 상단 "적용 기준일: YYYY-MM-DD" 메타데이터 필수 (MTU-A7 정책 동일) |
| 병렬 운영 기간 | MAJOR 업데이트 시 구버전 6개월 병렬 운영 (인증 전환 기간) |
| 인증 매핑 불변 | CSAP·ISMS-P 항목 ID (CSAP-DXX-YY, ISMS-P-XX.X.X)는 변경 불가. 폐지 시 `@deprecated` |
| 롤백 포인트 | 모든 MAJOR/MINOR 배포 전 Git 태그 생성 (`vX.Y.Z-pre-upgrade`) |

### 4. 롤백 절차

```
[롤백 조건]
  - Auditor Q-Gate G6 불통과
  - 현장 서비스 오류 발생
  - 기존 인증 영향 발견

[롤백 절차]
  1. 서비스 긴급 알림 발송 (30분 이내)
  2. Git 이전 태그로 복원
     git checkout vX.Y.Z-pre-upgrade
  3. 기존 증적 파일 복구 (불변 저장소에서 복원)
  4. Auditor 검증 재실행
  5. 사후 원인 분석 보고서 작성 (48시간 이내)
     → audit.jsonl에 롤백 이벤트 기록 (CSAP D-06)

[롤백 완료 기준]
  - 서비스 정상화 확인 (헬스체크 통과)
  - Auditor Q-Gate G6 재통과
  - 원인 분석 보고서 팀 공유 완료
```

### 5. 공공기관 SaaS 서비스 적용 절차

```
[신규 프레임워크 버전 출시]
    │
    ▼
[사용 기관 영향 분류]
    ├── PATCH: 자동 적용 (Flux GitOps 자동 동기화)
    ├── MINOR: 기관 동의 후 적용 (1주일 내 수락 권고)
    └── MAJOR: 기관 협의 + 일정 협의 (최소 3개월 준비 기간)
    │
    ▼
[스테이징 환경 선검증 (MTU-I2 Gitea CI/CD)]
    파이프라인: 빌드 → 단위 테스트 → 통합 테스트 → Auditor 검증
    │
    ▼
[단계적 프로덕션 적용 (카나리 배포)]
    10% 트래픽 → 오류율 확인 → 50% → 100%
    │
    ▼
[완료 확인 + audit.jsonl 기록]
```

## 합격 기준

1. 프레임워크 버전 체계 명시 (시맨틱 버저닝 MAJOR·MINOR·PATCH 정의 및 공공 규정 변경과의 매핑)
2. 규정 변경 → 프레임워크 업데이트 30일 SLA (MTU-A7 NFR-7 연동) 파이프라인 문서화
3. 기존 인증 영향 없이 업그레이드 가능한 설계 원칙 5개 이상 명시 (불변 증적 보존, 버전 격리 등)
4. 롤백 절차 포함 (조건·단계·완료 기준 명시)
