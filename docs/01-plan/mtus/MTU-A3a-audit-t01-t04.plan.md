## 목적

감리관이 사업의 전체 방향(T01), 요구사항 전수(T02), 시스템 구조(T03), FR 이행 근거(T04)를
한 번에 확인할 수 있도록 4개 핵심 산출물 템플릿을 완성본 수준으로 제공합니다.

**세부 목표**:
- **T01 사업계획서**: 행안부 감리기준 고시 제2023-1호 §5 형식 준수, 사업 목적·범위·일정·예산 기재
- **T02 요구사항정의서**: FR/NFR/INFR/AI-REQ/CC-REQ 전수 기재, 우선순위·출처·수용 기준 포함
- **T03 상세설계서**: 아키텍처 구성도 + DB 스키마 + API 명세 + CSAP 보안 설계 포함
- **T04 추적성 매트릭스**: FR ↔ 산출물 ↔ 테스트 ↔ CSAP 4방향 매핑 전수 완결

## T01 사업계획서 핵심 섹션 설계

행안부 정보화사업 감리기준 고시 제2023-1호 §5 「사업 착수 단계」 기준:

```
1. 사업 개요
   1.1 사업 명칭 및 목적
   1.2 추진 배경 및 필요성
   1.3 사업 범위 (In Scope / Out of Scope)
   1.4 기대 효과

2. 추진 전략
   2.1 개발 방법론 (MTU 분해 + PDCA)
   2.2 기술 스택 (k3s, Gitea, LM Studio 등)
   2.3 인증 목표 (CSAP 중/상, ISMS-P)

3. 추진 일정 (WBS)
   3.1 Phase 1~5 마일스톤
   3.2 감리 일정 (예비 + 본 감리)

4. 예산 계획
   4.1 개발 비용 항목
   4.2 인프라 비용 (WSL2 온프레미스)
   4.3 인증 비용 (CSAP, ISMS-P)

5. 추진 조직
   5.1 이해관계자 목록
   5.2 역할과 책임 (RACI)

6. 위험 관리
   6.1 위험 목록 및 대응 전략

[감리관 확인란]
□ 사업 목적 명확성 확인
□ 범위 정의 완전성 확인
□ 일정 현실성 확인
□ 예산 타당성 확인
```

## T02 요구사항정의서 핵심 섹션 설계

요구사항 ID 체계 (CLAUDE.md §3 기준):

| ID 유형 | 형식 | 예시 |
|---------|------|------|
| 기능 요구사항 | `FR-{모듈}.{번호}` | FR-1.1, FR-4.3 |
| 비기능 요구사항 | `NFR-{번호}` | NFR-1 (성능), NFR-2 (보안) |
| 인프라 요구사항 | `INFR-{번호}` | INFR-1 (k3s), INFR-2 (Gitea) |
| AI 연동 요구사항 | `AI-REQ-{번호}` | AI-REQ-1 (데이터 분류) |
| CC 하네스 요구사항 | `CC-REQ-{번호}` | CC-REQ-1 (Q-Gate) |

요구사항 테이블 구조:

```
| ID | 요구사항명 | 상세 설명 | 우선순위 | 출처 | 수용 기준 | 관련 CSAP |
|----|---------|---------|--------|------|---------|---------|
| FR-4.1 | 감리 산출물 T01 | 사업계획서 템플릿 제공 | P0 | 행안부 고시 §5 | T01 감리관 확인란 통과 | CSAP D-12 |
```

필수 포함 요구사항 그룹:
- FR-1.x: 기반 문서 (Getting Started, 참조 레이어)
- FR-2.x: CSAP 준수 (체크리스트, 구현 가이드)
- FR-3.x: N2SF 등급 분류 및 매핑
- FR-4.x: 감리 산출물 (T01~T07)
- FR-5.x: 인프라 (k3s, Gitea, GitOps)
- FR-6.x: AI 연동 (보안 게이트웨이, LM Studio)
- FR-7.x: 고급 기능 (OSCAL, 포털, 대시보드)
- NFR-1~10: 성능·보안·가용성·유지보수성 등

## T03 상세설계서 핵심 섹션 설계

```
1. 시스템 아키텍처
   1.1 전체 구성도 (k3s + Gitea + AI 게이트웨이)
   1.2 네트워크 구성도 (N2SF C/S/O 등급 분리)
   1.3 보안 영역 분리 (격리 영역 설계)

2. 데이터베이스 설계
   2.1 ER 다이어그램
   2.2 테이블 명세 (컬럼, 타입, 제약)
   2.3 암호화 대상 컬럼 목록 (CSAP D-09)

3. API 설계
   3.1 엔드포인트 목록 (OpenAPI 3.0 형식)
   3.2 인증·인가 흐름 (JWT + RBAC, CSAP D-08)
   3.3 에러 코드 표준

4. 보안 설계
   4.1 접근 통제 설계 (RBAC 역할 정의)
   4.2 암호화 설계 (AES-256 저장, TLS 1.3 전송)
   4.3 감사 로그 설계 (audit.jsonl 스키마)
   4.4 AI 보안 게이트웨이 설계 (N2SF 등급 → 라우팅)

5. 인터페이스 설계
   5.1 외부 연동 목록 (AI API, ISMS-P 시스템)
   5.2 데이터 교환 형식 (JSON/OSCAL)

[감리관 확인란]
□ 아키텍처 구성도 완비
□ DB 설계 완비
□ API 설계 완비
□ CSAP D-08/D-09 반영 여부
```
