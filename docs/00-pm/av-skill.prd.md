> **Date**: 2026-04-05
> **Status**: Draft

## Executive Summary

| 관점 | 내용 |
|------|------|
| **문제** | Claude Code 사용자가 bkit(50+ 스킬), ECC(150+ 스킬), claude-plugins-official(4+) 등 200개 이상의 플러그인 구성요소를 보유하고 있으나, 자연어 요구사항에 적합한 스킬/에이전트/워크플로우를 선택하지 못해 플러그인 활용률이 극히 낮다 |
| **솔루션** | `/av` 스킬이 사용자의 자연어 요구사항을 의도(Intent) 분류하고, 최적의 플러그인 구성요소를 자동 선택/순차-병렬 호출한 뒤 PDCA 흐름의 다음 단계를 안내하는 지능형 라우터 역할을 수행한다 |
| **기능/UX 효과** | 사용자는 "로그인 기능 만들어줘"처럼 자연어만 입력하면 최적 조합이 자동 실행되며, 플러그인명을 외울 필요 없이 원하는 작업을 완료할 수 있다 |
| **핵심 가치** | 200개+ 플러그인 구성요소의 진입 장벽을 제거하여 "설치만 하고 사용 못 하는" 문제를 해결하고, Claude Code 플러그인 생태계의 실질적 활용도를 극대화한다 |

# Part 1: Discovery 분석

## 1. 5-Step Discovery Chain

### Step 1: 기회 브레인스토밍 (Opportunity Brainstorm)

`/av` 스킬을 둘러싼 핵심 기회 영역:

| # | 기회 영역 | 설명 | 영향도 |
|---|-----------|------|--------|
| O1 | 자연어 의도 분류 | 사용자 요구사항을 6가지 의도(구현/리뷰/설계/배포/보안/학습)로 자동 분류 | 매우 높음 |
| O2 | 최적 구성요소 매핑 | 의도별 최적 스킬+에이전트+워크플로우 조합 자동 선택 | 매우 높음 |
| O3 | 실행 순서 결정 | 직렬/병렬 실행 순서를 자동 결정하여 사용자 개입 최소화 | 높음 |
| O4 | PDCA 흐름 통합 | 실행 완료 후 PDCA 다음 단계 자동 제안 | 높음 |
| O5 | 학습 곡선 제거 | 신입 개발자도 플러그인명 없이 자연어로 모든 기능 활용 | 매우 높음 |
| O6 | 컨텍스트 기반 개인화 | 프로젝트 레벨(Starter/Dynamic/Enterprise)과 기술 스택에 따른 맞춤 추천 | 중간 |
| O7 | 실행 결과 피드백 루프 | 사용자 만족도/수정 피드백을 학습하여 추천 정확도 지속 개선 | 중간 |

| A2 | LLM의 자연어 이해만으로 90% 이상의 정확도로 올바른 구성요소를 선택할 수 있다 | 기술 | 매우 높음 |

### Step 3: 가정 우선순위화 (Impact x Risk Matrix)

```
            높은 영향
               |
     A2(기술)  |  A1(기술)  A4(수요)
               |
               |  A3(가치)  A7(기술)
 ─────────────+──────────────────
               |
     A5(기술)  |  A6(가치)
               |
```

**최우선 검증 대상**:

3. **A4**: 자동 vs 수동 선택의 사용자 선호도

### 2.3 SWOT 분석

| | 긍정적 | 부정적 |
|---|--------|--------|
| **내부** | **강점(S)**: (1) 전체 플러그인 구성요소에 대한 완전한 접근 (2) 프로젝트 컨텍스트 인식 능력 (3) PDCA 흐름과 자연스러운 통합 (4) Claude Code Skills 2.0의 hot reload 지원 | **약점(W)**: (1) LLM 의도 분류의 불확실성 (2) 매핑 테이블 유지보수 부담 (3) 플러그인 버전 업데이트 시 동기화 필요 (4) 컨텍스트 윈도우 제약으로 전체 스킬 목록 로드 불가 |
| **외부** | **기회(T)**: (1) Claude Code 사용자 급증 (2) AI 코딩 도구 시장 성장 16%+ (3) 공공기관 AI 도입 확대로 규제 준수 자동화 수요 증가 (4) MCP 프로토콜 표준화로 플러그인 생태계 확장 | **위협(T)**: (1) Cursor/Copilot이 유사 기능 내장 가능 (2) Claude Code 자체적으로 스킬 자동 선택 기능 추가 가능 (3) 플러그인 구조 변경 시 매핑 무효화 (4) 과도한 자동화가 사용자 학습 기회 박탈 |

**SO 전략** (강점 x 기회):
- 프로젝트 컨텍스트 인식 + 공공기관 규제 자동 적용으로 차별화
- PDCA 통합 + MCP 표준 활용으로 생태계 확장

**WT 전략** (약점 x 위협):
- 매핑 테이블을 동적 생성 방식으로 전환하여 유지보수 부담 최소화
- 자동 실행 전 "실행 계획 미리보기"로 사용자 학습 기회 보존

# Part 5: PRD 본문 (8개 섹션)

## PRD-1. 개요 (Overview)

### 1.1 기능 설명

`/av` (Auto-Vibe Plugin Advisor)는 Claude Code CLI 스킬로, 사용자의 자연어 요구사항을 입력받아 최적의 플러그인 구성요소(스킬, 에이전트, 워크플로우)를 자동 선택하고 실행하는 지능형 라우터이다.

### 1.2 목적과 범위

- **목적**: 200개+ 플러그인 구성요소의 진입 장벽 제거
- **범위**: bkit v2.0.8 (36 스킬, 33 에이전트) + ECC v1.9.0 (150+ 스킬, 38 에이전트) + claude-plugins-official (4 플러그인) 전체 커버
- **범위 외**: 플러그인 자체 개발, 플러그인 설치/제거 관리

### 1.3 이해관계자

| 이해관계자 | 역할 | 관심사 |
|-----------|------|--------|
| 개발자 (최종 사용자) | `/av` 사용 | 학습 부담 없이 원하는 작업 완료 |
| 프레임워크 관리자 | 매핑 테이블 유지 | 구성요소 추가/변경 시 동기화 |
| bkit 플러그인 팀 | 스킬 배포 | 신규 스킬의 `/av` 자동 등록 |
| 공공기관 감리자 | 산출물 품질 | 올바른 에이전트 선택으로 감리 기준 준수 |

## PRD-4. 기술 아키텍처

### 4.1 스킬 구조

```
.claude/skills/av/
  SKILL.md              # 스킬 정의 (프론트매터 + 지침)
  references/
    intent-map.md       # 의도-구성요소 매핑 테이블
    skill-catalog.md    # 전체 스킬/에이전트 카탈로그
    execution-rules.md  # 실행 순서 규칙
  scripts/
    detect-context.sh   # 프로젝트 컨텍스트 감지
```

### 4.2 실행 흐름

```
[사용자 입력] "/av 로그인 기능 만들어줘"
    |
    v
[1. 컨텍스트 수집] (< 1초)
    - 프로젝트 레벨 감지 (Starter/Dynamic/Enterprise)
    - 기술 스택 감지 (package.json, go.mod 등)
    - PDCA 상태 확인 (.pdca-status.json)
    - 기존 코드 구조 파악
    |
    v
[2. 의도 분류] (< 2초)
    - LLM 프롬프트 기반 6-의도 분류
    - 복합 의도 분해
    - 신뢰도 계산
    |
    v
[3. 구성요소 선택] (< 1초)
    - intent-map.md 참조
    - 컨텍스트 기반 필터링
    - 최적 조합 결정
    |
    v
[4. 실행 계획 미리보기]
    +-- 선택된 구성요소 목록
    +-- 실행 순서 (직렬/병렬)
    +-- 예상 소요 시간
    +-- 선택 근거 설명
    |
    v
[5. 사용자 확인] "이 구성으로 진행할까요?"
    |
    v
[6. 자동 실행]
    +-- 직렬 구성요소 순차 실행
    +-- 병렬 구성요소 동시 실행
    +-- 에러 시 폴백
    |
    v
[7. 결과 요약 + 다음 단계 제안]
    +-- 실행 결과 요약
    +-- PDCA 다음 단계
    +-- 추가 추천 작업
```

### 4.3 의도 분류 프롬프트 설계

```markdown
당신은 사용자의 요구사항을 분석하여 의도를 분류하는 전문가입니다.

다음 6가지 의도 중 하나 이상을 선택하세요:
1. IMPLEMENT: 새로운 기능 구현, 코드 작성, 기능 추가
2. REVIEW: 코드 리뷰, 품질 검사, 보안 검토
3. DESIGN: 설계, 아키텍처, 계획 수립, PRD 작성
4. DEPLOY: 배포, 인프라, CI/CD, 롤백
5. SECURITY: 보안 감사, CSAP 점검, 취약점 분석
6. LEARN: 학습, 온보딩, 문서 조회, 개념 설명

사용자 요구사항: "{user_input}"
프로젝트 컨텍스트: {context}

출력 형식:
- primary_intent: {의도}
- secondary_intents: [{의도}, ...]
- confidence: {0.0-1.0}
- reasoning: {분류 근거}
```

```
    프레임워크 관리자 [관리]  |  최종 사용자 (개발자) [핵심]
                        |
    ────────────────────+──────────────────
                        |
    bkit 플러그인 팀 [정보]  |  공공기관 감리자 [모니터]
                        |
                    낮은 영향력
    높은 관심도          <->          낮은 관심도
```
