## 핵심 발견

### 1. Rate Limiting 정상 동작 (CSAP D-08 준수)

API Gateway에 Rate Limiter가 구현되어 있어 과도한 요청을 HTTP 429로 거부합니다. 이는 CSAP D-08 접근 통제 요건의 핵심 보안 기능이 정상 동작함을 증명합니다.

- **기준선 TPS**: 약 19 req/s (rate limit 허용 범위 추정)
- **실제 처리 능력**: 2,679~4,584 req/s (응답 생성 능력)
- **Rate Limit 이후**: 429 응답으로 안전하게 차단

### 2. 서버 에러 없음

50 동시 접속 부하에서도 서버 에러(5xx)는 0건. 서비스 안정성 우수.

### 3. 응답 시간

- Rate Limit 미적용 시: P50 < 1ms, P99 1~3ms (매우 우수)
- Rate Limit 적용 시: 큐잉으로 인한 대기 시간 증가

### 4. WSL2 환경 한계

단일 노드 WSL2 환경에서 50 동시 접속은 과부하 영역. 프로덕션에서는 다중 노드 + HPA로 해결.

## 권장 사항

1. **프로덕션 Rate Limit 조정**: 현재 ~19 TPS 허용 → 실제 트래픽 패턴에 맞게 조정
2. **HPA 설정**: CPU 70% 임계값으로 자동 스케일링
3. **부하 테스트 정기 실행**: 배포 후 성능 회귀 테스트
4. **모니터링 연동**: Grafana에서 TPS/P99/에러율 대시보드 연동
