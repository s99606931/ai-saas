## 1. 아키텍처 선택

**선택안**: Pragmatic Balance
- 문서 기반 갱신 관리 (자동화 시스템 없이 체크리스트 + 절차서)
- Gitea Issues 기반 리마인더 (외부 서비스 의존 없음)
- 3년 주기 + 매년 사후심사 이중 트랙 관리

## 2. 산출물 설계

### 2.1 갱신 주기 체크리스트 (FR-ISMS4.1)

```
docs/framework/03-isms-p/renewal/renewal-checklist.md
├── 1. 3년 갱신 주기 개요
│   ├── 인증 유효 기간: 발급일로부터 3년
│   ├── 매년 사후심사 의무 (연 1회)
│   └── 갱신심사: 만료 6개월 전 신청 필수
├── 2. 갱신 D-Day 카운트다운 체크리스트
│   ├── D-180: 갱신 준비 팀 구성 + 자가진단 착수
│   ├── D-150: 전년도 사후심사 결함 보완 완료 확인
│   ├── D-120: 101항목 증적 갱신 (변경 사항 반영)
│   ├── D-90:  갱신 심사 신청 + 인증기관 계약
│   ├── D-60:  증적 패키지 최종 정비 + 내부 모의심사
│   ├── D-30:  서류 제출 + 현장 심사 일정 확정
│   ├── D-14:  현장 심사 준비 (장소/인원/시스템)
│   ├── D-0:   갱신 현장 심사 (2~3일)
│   ├── D+14:  결함 보완 제출
│   └── D+30:  갱신 인증서 발급
├── 3. 연간 사후심사 준비 체크리스트
│   ├── 분기별 내부 점검 일정
│   ├── 증적 최신화 현황
│   ├── 변경사항 관리 (인증 범위 변경 시 신고)
│   └── 사후심사 당일 준비 사항
└── 4. 예외 상황 대응
    ├── 갱신 기한 임박 (D-30 미만)
    ├── 인증 범위 대폭 변경
    └── 인증기관 변경 시 절차
```

### 2.2 사후심사 절차서 (FR-ISMS4.2)

```
docs/framework/03-isms-p/renewal/annual-surveillance-procedure.md
├── 1. 사후심사 개요
│   ├── 목적: 인증 기준 지속 준수 확인
│   ├── 주기: 연 1회 (인증 후 1년 이내)
│   └── 범위: 전체 또는 일부 항목 (인증기관 결정)
├── 2. 연간 일정 템플릿
│   ├── 1월: 전년도 보안 실적 정리
│   ├── 3월: 1분기 내부 점검
│   ├── 6월: 2분기 내부 점검 + 사후심사 준비
│   ├── 7~8월: 사후심사 (예상)
│   ├── 9월: 3분기 내부 점검 + 결함 보완
│   └── 12월: 4분기 내부 점검 + 연간 보고서
├── 3. 사후심사 준비 절차
│   ├── 사전 제출 서류 목록
│   ├── 현장 심사 대응 체크리스트
│   └── 결함 보완 절차 (발견 시 30일 이내)
└── 4. 사후심사 후 조치
    ├── 결함 보완 보고서 작성
    ├── 증적 갱신
    └── 다음 사후심사 준비 착수
```

### 2.3 리마인더 설정 가이드 (FR-ISMS4.3)

```
docs/framework/03-isms-p/renewal/reminder-setup-guide.md
├── 1. Gitea Issues 기반 리마인더
│   ├── 갱신 D-180 이슈 자동 생성 (Gitea Actions cron)
│   ├── 사후심사 연간 이슈 자동 생성
│   └── 분기별 내부 점검 이슈 자동 생성
├── 2. Gitea Actions 크론 설정
│   ├── .gitea/workflows/isms-reminder.yml
│   └── cron: '0 9 1 */3 *' (분기 첫 영업일)
├── 3. 이메일/웹훅 알림 연동
│   ├── Gitea 웹훅 설정 방법
│   └── 담당자 알림 수신 설정
└── 4. 인증 범위 변경 신고 트리거 (FR-ISMS4.4)
    ├── 변경 사유 유형 (조직/시스템/서비스)
    ├── 신고 기한 (변경 후 30일 이내)
    └── 신고 양식 및 제출처
```
