# MTU-N237: Hotfix 파이프라인 자동화 -- Design

> **버전**: 1.0 | **작성일**: 2026-04-10

## 아키텍처

```
[hotfix/* 브랜치 push] → [Gitea Actions 트리거]
        ↓
[빌드 + 단위 테스트] → [보안 스캔 (Trivy+SBOM)]
        ↓
[스테이징 배포 + Smoke Test]
        ↓ (통과)
[프로덕션 배포 (수동 승인 게이트)]
        ↓ (실패)
[자동 롤백 + 알림]
```

## 파이프라인 단계 설계

1. **감지**: hotfix/* 브랜치 push 시 자동 트리거
2. **빌드**: Docker 이미지 빌드 (캐시 활용, 빠른 빌드)
3. **테스트**: 단위 + 통합 테스트 (범위 축소, 영향 범위만)
4. **보안**: Trivy 이미지 스캔 + SBOM 생성 (Critical/High 차단)
5. **스테이징 배포**: Helm upgrade → smoke test
6. **승인 게이트**: 프로덕션 배포 전 수동 승인 (필수)
7. **프로덕션 배포**: Flux 자동 배포 또는 수동 Helm
8. **검증**: 배포 후 헬스체크 + 에러율 확인
9. **롤백**: 에러율 증가 시 자동 롤백
