## 1. 개요

### 1.1 목적

ISMS-P 101항목 심사 시 필요한 증적을 자동으로 수집/분류/보고하는 파이프라인을 구축합니다. 기존 CSAP 증적 인프라(audit.jsonl, Gitea CI/CD)를 확장하여 ISMS-P 항목별 자동 태깅 및 보고서 생성을 지원합니다.

### 1.2 목표

| 목표 | 지표 | 현재 | 목표 |
|------|------|------|------|
| 심사 준비 공수 절감 | 준비 기간 (월) | 6개월 | 2개월 |
| 증적 누락 | 누락 항목 수 | 미측정 | 0건 |
| 자동 수집률 | 자동/전체 | 0% | 60% |
| CSAP 증적 재활용 | 재활용/전체 | 0% | 45% |

## 3. 증적 소스별 수집 방법

### 3.1 audit.jsonl (감사 로그)

```
수집 대상:
- 사용자 인증/인가 이벤트
- 데이터 접근/수정 이벤트
- 관리자 작업 이벤트
- 보안 위반 탐지 이벤트

ISMS-P 매핑:
- 2.5.1~2.5.6 (인증/권한)
- 2.9.3~2.9.4 (로그 관리)
- 2.11.1~2.11.5 (침해 대응)

수집 주기: 실시간 (append-only)
보존 기간: 3년 (ISMS-P 인증 유효기간)
```

### 3.2 Gitea CI/CD 로그

```
수집 대상:
- 빌드/테스트 결과
- 보안 스캔 결과 (Trivy, npm audit, ZAP)
- 배포 이력
- 코드 리뷰 이력

ISMS-P 매핑:
- 2.10.9 (취약점 점검)
- 2.12.5 (시큐어 코딩)
- 2.12.6 (소스 관리)

수집 주기: 매 빌드/배포 시
보존 기간: 3년
```

### 3.3 시스템 로그

```
수집 대상:
- 서비스 헬스체크 결과
- 리소스 사용량 (CPU/메모리/디스크)
- 네트워크 트래픽 이상
- 에러/경고 로그

ISMS-P 매핑:
- 2.9.2 (성능 및 장애 관리)
- 2.10.1 (보안 시스템 운영)
- 2.10.7 (패치 관리)

수집 주기: 5분 간격
보존 기간: 1년
```

## 5. 보고서 자동 생성

### 5.1 일간 집계

```yaml
# .gitea/workflows/isms-p-daily-evidence.yml
name: ISMS-P 일간 증적 집계

on:
  schedule:
    - cron: '0 23 * * *'  # 매일 23:00 UTC

jobs:
  collect-daily:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: 증적 집계
        run: |
          # audit.jsonl에서 금일 이벤트 추출
          DATE=$(date +%Y-%m-%d)
          grep "$DATE" .claude/audit.jsonl > "isms-evidence/${DATE}.jsonl" || true
          echo "일간 증적 집계 완료: ${DATE}"
```
