## 1. 개요

### 1.1 목적

ISMS-P 인증 유효기간(3년) 동안 매년 실시하는 사후심사에 체계적으로 대응하기 위한 표준 절차서입니다.

### 1.2 법적 근거

- 정보통신망법 제47조 (정보보호 관리체계 인증)
- 개인정보보호법 제32조의2 (개인정보 보호 인증)
- ISMS-P 인증 등에 관한 고시 (과기정통부/개인정보보호위원회)

### 1.3 사후심사 주기

- **주기**: 인증 후 매 1년 이내 (연 1회)
- **범위**: 인증기관이 선정한 항목 (전체 또는 일부)
- **불이행 시**: 인증 취소 가능

## 4. 연간 필수 활동

### 4.1 보안 교육 (연 1회 이상)

- 대상: 전 임직원 + 외주 인력
- 내용: 정보보호 정책, 개인정보보호, 보안 사고 대응
- 산출물: 교육 계획서, 출석부, 교육 자료, 평가 결과

### 4.2 취약점 점검 (반기 1회 이상)

- 대상: 전체 서비스 + 인프라
- 도구: Trivy (컨테이너), npm audit (의존성), OWASP ZAP (웹)
- 산출물: 취약점 점검 보고서, 보완 조치 결과

### 4.3 위험 평가 갱신 (연 1회)

- 방법: 자산 변경/신규 위협/취약점 반영
- 산출물: 위험 평가 보고서 (갱신), 잔여 위험 수용 기록

### 4.4 내부 감사 (연 1회)

- 방법: 독립적 내부 감사팀 (또는 외부 위탁)
- 범위: 101항목 전수 또는 중요 항목 선별
- 산출물: 내부 감사 보고서, 개선 조치 계획서

### 4.5 경영진 보고 (반기 1회)

- 내용: 보안 현황, 사고 이력, 개선 활동, 예산 소요
- 산출물: 경영진 보고서

## 5. 기록 관리

### 5.1 기록 보존 기간

| 기록 유형 | 보존 기간 | 보존 방법 |
|---------|---------|---------|
| 심사 결과서 | 인증 유효기간 + 1년 | 원본 보관 |
| 증적 자료 | 인증 유효기간 + 1년 | Git 저장소 |
| 감사 로그 | 최소 1년 | append-only 파일 |
| 교육 기록 | 3년 | 인사 시스템 |
| 보안사고 기록 | 5년 | 사고 관리 시스템 |

### 5.2 기록 무결성 보장

- 모든 문서: Git 형상 관리 (커밋 이력 = 변경 추적)
- 감사 로그: append-only + SHA-256 해시 검증
- 인쇄물: 날짜 + 담당자 서명 + 보관 번호
