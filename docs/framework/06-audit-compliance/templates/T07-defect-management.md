## 2. 결함 식별 체계

### 2.1 결함 ID 형식

```
DEF-{MTU}-{일련번호}
예: DEF-C3-001, DEF-A1-003
```

### 2.2 결함 심각도 분류

| 심각도 | 정의 | 조치 기한 | 감리 영향 | 예시 |
|--------|------|---------|---------|------|
| CRITICAL | 시스템 운영 불가 또는 보안 사고 위험 | 24시간 이내 | 즉시 보고 | 인증 우회, DB 노출, 암호화 누락 |
| HIGH | 핵심 기능 오동작 또는 CSAP 통제 미적용 | 3영업일 이내 | 감리 불통과 | RBAC 미적용, 감사 로그 누락 |
| MEDIUM | 부분 기능 이상 또는 보안 권고 미준수 | 1주일 이내 | 조건부 통과 | 감사 로그 일부 필드 누락 |
| LOW | 경미한 오류 | 다음 릴리즈 | 권고 사항 | UI 오탈자, 주석 오류, 문서 미갱신 |

## 3. 결함 처리 흐름

```
시험 실행 (T06)
    |
    v
결함 발견 --> T07 등록 (결함 ID 부여, 심각도 분류)
    |
    v
원인 분석 --> 조치 계획 수립 (담당자, 기한 명시)
    |
    v
조치 실시 --> 조치 완료 기록 (코드 변경, 설정 수정 등)
    |
    v
재시험 실행 --> 재시험 결과 기록
    |
    +-- 통과 --> 결함 종결 (상태: CLOSED)
    +-- 불통과 --> 조치 계획 재수립 (상태: REOPENED)
```

## 6. 에스컬레이션 절차

| 조건 | 에스컬레이션 대상 | 조치 |
|------|--------------|------|
| CRITICAL 발견 | CISO (즉시) | 긴급 대응팀 소집, 24시간 내 조치 |
| HIGH 미결 3영업일 초과 | 팀장 | 조치 지연 사유 보고 + 대안 검토 |
| 동일 결함 재발 | CISO + 감리관 | 근본 원인 재분석 + 프로세스 개선 |
| 총 미결 10건 초과 | 경영진 | 일정 조정 검토 |
