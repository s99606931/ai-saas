## 2. 추진 전략

### 2.1 개발 방법론

| 항목 | 내용 |
|------|------|
| 방법론 | MTU(Minimum Testable Unit) 분해 + PDCA 사이클 |
| Phase 구조 | Phase 1(기반) → Phase 2(핵심보안) → Phase 3(인프라) → Phase 4(고급) → Phase 5(확장) |
| 품질 관리 | 7단계 Q-Gate (G1~G7), matchRate 90%+ 합격 기준 |
| 에이전트 분업 | Implementer → Reviewer → Auditor → Tester → Refactorer |

### 2.2 기술 스택

| 구성 요소 | 기술 | 선택 근거 |
|---------|------|---------|
| 컨테이너 오케스트레이션 | k3s (Kubernetes 경량) | WSL2 환경 최적화, 폐쇄망 운영 |
| CI/CD | Gitea + Gitea Actions | 외부 의존 없는 자립형 파이프라인 |
| GitOps | Flux v2 | Pull 모드, 폐쇄망 적합 |
| 레지스트리 | Harbor | 취약점 스캔 + 서명 검증 내장 |
| 모니터링 | OpenTelemetry + Prometheus | 통합 관측 가능성 |
| AI (온프레미스) | LM Studio (Llama) | C/S등급 데이터 처리, 외부 전송 없음 |
| AI (외부) | Claude API | O등급 데이터만, PII 마스킹 후 |
