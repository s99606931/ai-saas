# ISMS-P 2027 의무화 대응 인증 취득 가이드

> MTU-E1 | FR-8.4 | 적용 기준일: 2026-04-05
> 참조: MTU-C6a (관리체계 체크리스트), MTU-C6b (보호/개인정보 + 증적 자동화), MTU-A7 (N2SF 모니터링)
> 의존: CSAP 표준등급 인증 선행 취득 권장

## 1. 개요

### 1.1 ISMS-P 2027 의무화 배경

과학기술정보통신부는 2027년 7월 1일부터 정보통신서비스 제공자(공공 SaaS 포함)에 대해
ISMS-P(정보보호 및 개인정보보호 관리체계) 인증을 의무화합니다.

| 항목 | 내용 |
|------|------|
| 근거 법령 | 정보통신망법 제47조, 개인정보보호법 제32조의2 |
| 시행일 | 2027-07-01 |
| 대상 | 연매출 100억 이상 또는 일평균 이용자 100만 명 이상 정보통신서비스 제공자 |
| 확대 대상 | 공공기관 클라우드 서비스(SaaS) 제공자 (행안부 고시에 의한 확대 적용) |
| 인증 기관 | 한국인터넷진흥원(KISA) |
| 인증 유효기간 | 3년 (연 1회 사후 심사) |
| 벌칙 | 미인증 시 과태료 3천만 원 이하 + 서비스 제한 가능 |

### 1.2 적용 대상: 공공기관 SaaS

본 프레임워크 기반 공공기관 SaaS 서비스는 다음 조건에 해당합니다.

- 공공기관에 클라우드 서비스를 제공하는 SaaS 사업자
- CSAP(클라우드 보안 인증제) 중/상 등급 인증 대상
- 개인정보 처리를 수반하는 서비스 (주민등록번호, 건강정보 등)

### 1.3 CSAP 이중 인증 전략 요약

```
CSAP 79항목 ←→ ISMS-P 101항목

중복 항목: 40개 (완전 30 + 부분 10)
→ CSAP 인증 선행 취득 시 ISMS-P 심사 부담 40% 절감

전략: CSAP 먼저 → CSAP 증적으로 ISMS-P 중복 항목 자동 대응
```

### 3.2 2단계: 현장 심사 (인터뷰 + 실증)

**기간**: 서류 심사 통과 후 약 1~2주 현장 방문
**목적**: 서류상 관리체계가 실제 운영되는지 확인

#### 심사원 인터뷰 대비 Q&A

| 역할 | 예상 질문 | 모범 답변 요점 |
|------|---------|-------------|
| CISO | "정보보호 정책을 어떻게 수립·공표했는가?" | 연 1회 정책 검토·갱신 절차, 전 직원 공표 이력 제시 |
| CISO | "위험 관리는 어떻게 수행하는가?" | 자산 기반 위험 평가 → 위험 처리 계획 → 잔여 위험 수용 절차 |
| 보안담당자 | "접근 통제는 어떻게 운영하는가?" | RBAC + JWT + MFA (CSAP D-08 증적 활용) |
| 보안담당자 | "암호화는 어떻게 적용하는가?" | AES-256 저장, TLS 1.3 전송 (CSAP D-09 증적 활용) |
| 보안담당자 | "침해사고 대응 절차는?" | 5단계: 탐지→분석→차단→복구→보고 (CSAP D-06 증적 활용) |
| 개발팀장 | "시큐어 코딩은 어떻게 적용하는가?" | ESLint 보안 규칙 + Trivy SAST + 코드리뷰 체크리스트 |
| 개발팀장 | "개인정보 처리 동의는 어떻게 받는가?" | 명시적 동의 수집 → consent 이벤트 audit.jsonl 기록 |
| DBA | "개인정보 파기 절차는?" | 보유기간 만료 자동 파기 스케줄러 + 파기 로그 audit.jsonl |

### 3.3 3단계: 보완 조치

**기간**: 현장 심사 종료 후 최대 60일
**목적**: 심사 과정에서 발견된 결함 항목 보완

#### 결함 분류 및 대응 기준

| 결함 등급 | 정의 | 보완 기한 | 대응 방법 |
|---------|------|---------|---------|
| 중대 결함 | 관리체계 근본적 미비 | 30일 이내 | 긴급 보완 + 경영진 보고 + 재심사 요청 가능 |
| 보통 결함 | 일부 통제 항목 미흡 | 45일 이내 | 보완 조치 후 증적 제출 |
| 경미 결함 | 문서/절차 보완 수준 | 60일 이내 | 문서 수정 후 증적 제출 |

#### 자동 보완 추적 (MTU-A7 연동)

```
현장 심사 결함 발견
    │
    ▼
Gitea Issue 자동 생성
    ├── label: isms-p-deficiency
    ├── label: severity-{중대|보통|경미}
    ├── assignee: 담당자 자동 배정
    └── milestone: ISMS-P-보완조치-{심사일}
    │
    ▼
보완 작업 완료 → PR merge
    │
    ▼

    │
    ▼
보완 결과 보고서 자동 생성 → KISA 제출
```

#### 인증 갱신 자동 알림 워크플로우

```yaml
# .gitea/workflows/isms-p-renewal-alert.yml
name: ISMS-P 인증 갱신 알림

on:
  schedule:
    - cron: '0 9 * * 1'  # 매주 월요일 09:00

env:
  CERT_EXPIRY_DATE: '2030-07-01'  # 인증 만료일 (인증 후 설정)

jobs:
  check-renewal:
    runs-on: ubuntu-latest
    steps:
      - name: 만료일 계산
        run: |
          DAYS_REMAINING=$(( ($(date -d "$CERT_EXPIRY_DATE" +%s) - $(date +%s)) / 86400 ))
          if [ $DAYS_REMAINING -le 180 ]; then
            echo "ISMS-P 인증 갱신 필요: ${DAYS_REMAINING}일 남음"
            # Gitea Issue 자동 생성
            curl -X POST "$GITEA_URL/api/v1/repos/$REPO/issues" \
              -H "Authorization: token $GITEA_TOKEN" \
              -d "{
```
