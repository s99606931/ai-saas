## 목적

PR 코드리뷰 및 문서 리뷰 시 사용하는 체크리스트입니다. **이 문서만 참조하여 리뷰 1회를 완료**할 수 있도록 설계되었습니다. 다른 문서를 열 필요 없이 아래 항목을 순서대로 점검하세요.

---

## 사용 방법

1. PR이 코드 변경이면 **섹션 1: 코드 리뷰**를 사용
2. PR이 문서 변경이면 **섹션 2: 문서 리뷰**를 사용
3. 코드 + 문서 모두 변경이면 양쪽 모두 사용
4. 미통과 항목이 있으면 PR에 변경 요청(Request Changes)

## 섹션 1: 코드 리뷰 체크리스트

### 1.1 보안 (CSAP/OWASP -- Q-GATE G5 대응)

| # | 항목 | 확인 내용 | 심각도 | 확인 |
|---|------|---------|--------|------|
| S1 | 하드코딩 시크릿 없음 | API 키, 비밀번호, 토큰이 코드에 직접 포함되어 있지 않음 | Critical | ☐ |
| S2 | RBAC 접근 통제 적용 | 모든 API 엔드포인트에 `verifyToken` + `hasPermission` 호출 존재 | Critical | ☐ |
| S3 | 입력 검증 적용 | 모든 API 입력에 Zod 스키마 또는 동등한 검증 적용 | Critical | ☐ |
| S4 | SQL 인젝션 방지 | 매개변수화 쿼리 사용, 직접 문자열 결합 없음 | Critical | ☐ |
| S5 | XSS 방지 | 사용자 입력의 DOM 삽입 시 DOMPurify 적용 | High | ☐ |
| S6 | 에러 메시지 안전 | 에러 응답에 스택 트레이스, DB 정보, 내부 경로 미포함 | High | ☐ |
| S7 | 감사 로그 | 민감 작업(생성/수정/삭제/권한변경)에 `auditLog()` 호출 존재 | High | ☐ |
| S8 | N2SF 데이터 통제 | AI API 호출 시 C/S등급 데이터 전송 차단 확인 | Critical | ☐ |
| S9 | 암호화 적용 | 민감 데이터 저장 시 AES-256, 비밀번호 bcrypt 해시 | High | ☐ |
| S10 | TLS 전송 | HTTP 평문 통신 없음, HTTPS/TLS 1.3+ 사용 | High | ☐ |
