## 목적

프레임워크의 모든 문서에서 사용하는 요구사항 ID 체계를 정의합니다. 일관된 ID 체계는 감리 시 추적성 매트릭스(T07)의 기반이 됩니다.

**핵심 원칙**: 모든 요구사항에 고유 ID가 부여되어야 하며, ID가 없는 요구사항 = 감리 결함입니다.

---

## 1. ID 유형 정의

### 5종 요구사항 ID

| ID 유형 | 패턴 | 설명 | 예시 |
|---------|------|------|------|
| 기능 요구사항 | `FR-{모듈}.{번호}` | 시스템이 수행해야 하는 기능 | FR-1.1, FR-2.3, FR-0.6 |
| 비기능 요구사항 | `NFR-{번호}` | 성능, 보안, 가용성 등 품질 속성 | NFR-1, NFR-12 |
| 인프라 요구사항 | `INFR-{번호}` | 하드웨어, 네트워크, 클라우드 환경 | INFR-1, INFR-5 |
| AI 연동 요구사항 | `AI-REQ-{번호}` | AI/LLM API 연동 관련 | AI-REQ-1, AI-REQ-3 |
| CC 하네스 요구사항 | `CC-REQ-{번호}` | Claude Code 하네스 관련 | CC-REQ-1, CC-REQ-2 |

## 2. 모듈 번호 체계

FR ID의 모듈 번호는 프레임워크 구조에 대응합니다.

| 모듈 번호 | 모듈명 | 프레임워크 디렉토리 | Phase | MTU 범위 |
|---------|--------|----------------|-------|---------|
| 0 | Foundation | `00-getting-started/`, `01-dev-standards/`, `99-references/` | 1 | MTU-F1~F6 |
| 1 | CSAP 표준등급 | `06-csap-standard/` | 2 | MTU-C1~C3 |
| 2 | N2SF | `06-csap-standard/` (N2SF 섹션) | 2 | MTU-C4~C5 |
| 3 | Infrastructure | `05-infra/` | 2 | MTU-I1~I5 |
| 4 | AI Integration | (Phase 3) | 3 | MTU-A1~A2 |
| 5 | Audit Compliance | `03-audit-docs/`, `04-audit-compliance/` | 1, 3 | MTU-F5, MTU-A3~A4 |

### FR 번호 부여 규칙

```
FR-{모듈}.{일련번호}

예시:
  FR-0.1  -- 모듈 0(Foundation)의 첫 번째 요구사항
  FR-1.12 -- 모듈 1(CSAP 표준등급)의 12번째 요구사항
  FR-3.5  -- 모듈 3(Infrastructure)의 5번째 요구사항
```

**규칙**:
- 일련번호는 1부터 시작, 순차 증가
- 삭제된 번호는 재사용하지 않음 (이력 추적성 유지)
- 하위 요구사항: FR-1.1.a, FR-1.1.b 형식 허용 (최대 1단계 하위)

## 3. NFR/INFR/AI-REQ/CC-REQ 번호 부여 규칙

```
NFR-{일련번호}     -- 예: NFR-1, NFR-2, ..., NFR-20
INFR-{일련번호}    -- 예: INFR-1, INFR-2, ..., INFR-10
AI-REQ-{일련번호}  -- 예: AI-REQ-1, AI-REQ-2, AI-REQ-3
CC-REQ-{일련번호}  -- 예: CC-REQ-1, CC-REQ-2, CC-REQ-3
```

**규칙**:
- 모듈 구분 없이 단일 순차 번호 사용
- 프레임워크 전체에서 고유 (중복 금지)
- 삭제 시 재사용 금지

## 4. CSAP 항목 ID 체계

CSAP 통제항목은 별도 체계를 사용합니다 (KISA 표준).

```
CSAP-D{분야번호}-{항목번호}

예시:
  CSAP-D01-01 -- D01(정보보호 정책) 분야 1번 항목
  CSAP-D08-03 -- D08(접근 통제) 분야 3번 항목
  CSAP-D12-01 -- D12(시스템 개발 보안) 분야 1번 항목
```

**CSAP 분야 목록**:

| 분야 코드 | 분야명 | 항목 수 (표준등급) |
|---------|--------|---------------|
| D01 | 정보보호 정책 | 4 |
| D02 | 정보보호 교육 | 4 |
| D03 | 인적 보안 | 5 |
| D04 | 자산 관리 | 4 |
| D05 | 물리적 보안 | 4 |
| D06 | 침해사고 관리 | 5 |
| D07 | 재해복구 | 4 |
| D08 | 접근 통제 | 12 |
| D09 | 암호화 | 4 |
| D10 | 네트워크 보안 | 10 |
| D11 | 운영 관리 | 8 |
| D12 | 시스템 개발 보안 | 10 |
| D13 | 기타 보안 | 5 |
| **합계** | — | **79** |

## 5. 교차 참조 규칙

### FR <-> CSAP 교차 참조

모든 기능 요구사항(FR)은 관련 CSAP 항목과 교차 참조되어야 합니다.

| 표기 방법 | 사용 위치 | 예시 |
|---------|---------|------|
| FR 테이블의 "CSAP 항목" 열 | T02 요구사항정의서 | `FR-1.1 → CSAP-D08-01~05` |
| 문서 내 인라인 참조 | 설계/구현 문서 | `(CSAP-D09-01 준수)` |
| 추적성 매트릭스 | T07 추적성 매트릭스 | FR → 설계 → 코드 → CSAP |

### 미매핑 처리

- FR에 CSAP 항목이 매핑되지 않은 경우: "N/A (CSAP 해당 없음)" 명시
- CSAP 항목에 FR이 매핑되지 않은 경우: 감리 결함으로 플래그

### 예시 1: Plan 문서에서의 사용

```markdown

| ID | 요구사항 | 수용 기준 |

```
