## 2. 기능 요구사항 (FR)

> **작성 지침**: 모든 기능 요구사항에 FR-{모듈}.{번호} 형식의 ID를 부여합니다. CSAP 항목과의 교차 참조를 반드시 기입합니다.

### 요구사항 ID 체계

| ID 유형 | 패턴 | 예시 | 적용 범위 |
|---------|------|------|---------|
| 기능 요구사항 | `FR-{모듈}.{번호}` | FR-1.1, FR-2.3 | 시스템 기능 요건 |
| 비기능 요구사항 | `NFR-{번호}` | NFR-1, NFR-12 | 성능/보안/가용성 |
| 인프라 요구사항 | `INFR-{번호}` | INFR-1, INFR-5 | HW/SW/네트워크 |
| AI 연동 요구사항 | `AI-REQ-{번호}` | AI-REQ-1 | AI/LLM API 관련 |
| CC 하네스 요구사항 | `CC-REQ-{번호}` | CC-REQ-1 | Claude Code 하네스 |

### 모듈 번호 체계

| 모듈 번호 | 모듈명 | 설명 |
|---------|--------|------|
| 0 | Foundation | 프레임워크 기반 (Getting Started, 표준, 참조) |
| 1 | CSAP 표준등급 | 79항목 체크리스트, 분야별 통제 |
| 2 | N2SF | 데이터 등급 분류, 보안 영역 매핑 |
| 3 | Infrastructure | k3s, Gitea, 네트워크, 모니터링 |
| 4 | AI Integration | AI 게이트웨이, LM Studio |
| 5 | Audit Compliance | 감리 산출물 T01~T07 |

### 기능 요구사항 목록

## 7. 요구사항 우선순위

> **작성 지침**: MoSCoW 기법을 적용합니다. Must 항목은 감리 필수 검증 대상입니다.

### MoSCoW 분류 기준

| 등급 | 의미 | 비율 권장 |
|------|------|---------|
| **Must** | 필수 구현. 미구현 시 감리 결함 | 60~70% |
| **Should** | 구현 권장. 미구현 시 조건부 적합 | 20~25% |
| **Could** | 가능하면 구현. 미구현 시 영향 없음 | 5~10% |
| **Won't** | 이번 사업 범위 아님. 차기 사업으로 이관 | 0~5% |

## 8. 추적성 준비

> **작성 지침**: T07 추적성 매트릭스(Phase 3 MTU-A3c)와 연계하기 위한 기반을 정의합니다. 각 요구사항이 설계->구현->테스트까지 추적 가능해야 합니다.

### 추적성 방향

```
[4방향 추적성]
요구사항(FR) ↔ 설계(T03/T04) ↔ 코드(src/) ↔ 테스트(T05/T06)
     ↕                                              ↕
  CSAP 항목 (CSAP-DXX-YY)                    감리 결과 (T07)
```
