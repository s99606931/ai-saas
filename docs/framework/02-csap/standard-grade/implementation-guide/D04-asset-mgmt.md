## 분야 개요

자산 관리는 조직의 **모든 IT 자산을 식별, 분류, 관리, 폐기**하는 운영 통제입니다. 클라우드 환경에서는 물리적 자산 외에 가상 자산(VM, 컨테이너, 스토리지), 소프트웨어 라이선스, 데이터도 포함됩니다.

**핵심 키워드**: 자산 목록, 분류 등급, 책임자 지정, 미디어 관리, 폐기 절차

## CSAP-D04-01: IT 자산 목록 관리

> **중요도**: 상 | **구분**: 필수

### 구현 목표

모든 IT 자산(서버, 네트워크 장비, 소프트웨어 등)을 대장으로 관리하고 정기적으로 갱신한다.

### 구현 방법

1. **자산 분류 체계 정의**

| 대분류 | 중분류 | 예시 |
|-------|-------|------|
| 하드웨어 | 서버 | 물리 서버, VM 인스턴스 |
| | 네트워크 | 스위치, 방화벽, 라우터 |
| | 단말기 | PC, 노트북, 모바일 |
| 소프트웨어 | OS | Linux, Windows Server |
| | 미들웨어 | Nginx, PostgreSQL, Redis |
| | 애플리케이션 | 자체 개발 SaaS 앱 |
| 데이터 | 데이터베이스 | PostgreSQL DB, 백업 |
| | 문서 | 설계 문서, 운영 매뉴얼 |
| 클라우드 | 컨테이너 | k3s Pod, Docker 이미지 |
| | 스토리지 | PV, PVC, S3 호환 |
| | 네트워크 | VPC, 서브넷, SecurityGroup |

2. **자산 대장 작성**

## CSAP-D04-02: 자산 분류 및 등급

> **중요도**: 상 | **구분**: 필수

### 구현 목표

자산별 중요도를 분류(상/중/하)하고 분류 기준을 문서화한다.

### 구현 방법

1. **분류 기준표**

| 등급 | 기밀성 영향 | 무결성 영향 | 가용성 영향 | 예시 |
|------|----------|----------|----------|------|
| **상** | 유출 시 심각한 피해 | 변조 시 업무 마비 | 장애 시 서비스 중단 | DB 서버, 인증 시스템, 고객 데이터 |
| **중** | 유출 시 제한적 피해 | 변조 시 업무 지연 | 장애 시 부분 영향 | 개발 서버, 내부 문서, 로그 시스템 |
| **하** | 유출 시 경미한 영향 | 변조 시 경미한 영향 | 장애 시 영향 미미 | 테스트 환경, 공개 문서, 개발 도구 |

2. **분류 절차**
   - 자산별 CIA(기밀성/무결성/가용성) 영향 평가
   - 3개 항목 중 최고 등급을 자산 등급으로 결정
   - 등급 결과를 자산 대장에 기록

3. **분류 이력 관리**: 등급 변경 시 사유와 일자 기록

### 필요 증거 자료

| 증거 | 형태 |
|------|------|
| 자산 분류 기준표 | 문서 |
| 등급 목록 (자산 대장에 포함) | 테이블 |
| 분류 이력 (변경 사유 포함) | 기록 |

## CSAP-D04-03: 자산 책임자 지정

> **중요도**: 중 | **구분**: 필수

### 구현 목표

모든 IT 자산에 책임자를 지정하고 변경 이력을 관리한다.

### 구현 방법

1. **책임자 지정 원칙**
   - 자산 "소유자"는 해당 자산의 보안 관리 책임을 가짐
   - 등급 "상" 자산: 팀장급 이상 지정
   - 등급 "중/하" 자산: 담당자급 지정 가능
   - 1인 다건 자산 책임 가능 (과부하 주의)

2. **책임자 역할**
   - 자산 접근 권한 승인/취소
   - 자산 보안 설정 점검
   - 자산 현황 변경 시 대장 갱신 요청
   - 폐기 시 승인

### 필요 증거 자료

| 증거 | 형태 |
|------|------|
| 자산별 책임자 목록 (자산 대장에 포함) | 테이블 |
| 책임자 변경 이력 | 기록 |

## CSAP-D04-04: 미디어 관리

> **중요도**: 중 | **구분**: 필수

### 구현 목표

이동식 저장매체(USB, 외장하드 등)의 반입/반출을 통제한다.

### 구현 방법

1. **미디어 관리 정책**
   - USB 사용 제한 (DLP 솔루션 또는 정책)
   - 반입/반출 시 승인 절차
   - 암호화 저장매체만 허용 (선택)

2. **미디어 관리 대장**

| 미디어 번호 | 유형 | 용량 | 사용자 | 반입일 | 반출일 | 승인자 | 상태 |
|-----------|------|------|--------|--------|--------|--------|------|
| USB-001 | USB 3.0 | 64GB | 김개발 | 2026.01.10 | 2026.01.10 | 이보안 | 반출 완료 |
| HDD-001 | 외장 HDD | 1TB | 박운영 | 2026.02.01 | - | 이보안 | 보관 중 |

3. **클라우드 환경 특수 사항**
   - 물리 미디어 최소화 (클라우드 스토리지 활용)
   - 데이터 전송 시 암호화 필수 (TLS 1.3+)
   - 백업 미디어도 동일 통제 적용

### 필요 증거 자료

|------|------|
| 미디어 관리 대장 | 테이블 |
| 반입/반출 기록 | 기록 |
| 미디어 관리 정책 | 문서 |

## CSAP-D04-05: 자산 폐기 절차

> **중요도**: 상 | **구분**: 필수

### 구현 목표

IT 자산 폐기 시 데이터를 완전히 삭제하고 복원 불가 상태를 보장한다.

### 구현 방법

1. **폐기 절차**

```
폐기 신청 -> 자산 책임자 승인 -> 데이터 삭제 -> 삭제 검증 -> 물리적 처리 -> 대장 갱신
```

2. **데이터 삭제 방법**

| 자산 유형 | 삭제 방법 | 기준 |
|---------|---------|------|
| HDD (자기식) | DoD 5220.22-M (3회 덮어쓰기) 또는 물리적 파쇄 | NIST SP 800-88 |
| SSD | Secure Erase 명령 + 물리적 파쇄 | 제조사 도구 |
| 클라우드 스토리지 | PV 삭제 + reclaimPolicy: Delete | k8s 설정 |
| 데이터베이스 | DROP + 스토리지 삭제 | 검증 쿼리 |
| 컨테이너 이미지 | crictl rmi + 레지스트리 삭제 | 이미지 목록 확인 |

3. **삭제 검증**: 삭제 후 복구 시도 -> 복원 불가 확인

### 심사 시 주의사항

> C2a-GAP-1 수정 (2026-04-05): 자산관리 분야(D04) 심사 준비 체크포인트 추가

D04 자산 관리 분야는 현장 심사 시 다음 사항이 자주 지적됩니다.

1. **자산 대장 최신화 여부**
   - 최근 분기 이내에 갱신된 자산 대장 필수. 1년 이상 미갱신 시 불합격 판정 가능
   - 갱신 담당자와 갱신 일자가 자산 대장 내에 명시되어야 함
   - 심사 당일 현장에서 실제 자산과 자산 대장 일치 여부 확인 (샘플링 점검)

2. **폐기 절차 준수**
   - 자산 폐기 확인서(서명본)가 물리적으로 보존되어 있어야 함. 전자 문서만으로 불충분한 경우 있음
   - 클라우드 환경: PV 삭제 명령 실행 로그 + reclaimPolicy 설정 캡처가 폐기 증적으로 인정
   - SSD/NVMe 폐기 시 `Secure Erase` 실행 로그 또는 물리 파쇄 사진 필수

3. **자산 책임자 지정 현황**
   - 자산 대장의 책임자 칸이 공란이거나 퇴직자로 남아 있는 경우 즉시 지적
   - 책임자 변경 이력을 별도 기록하거나 자산 대장 비고란에 변경 일자와 사유 기재 필요

4. **미디어 관리 대장 실효성**
   - 반입/반출 기록이 전혀 없으면 형식적 운영으로 판단될 수 있음
   - "USB 사용 없음" 상태라도 정책 문서와 DLP 설정 화면을 증적으로 제출 권장

5. **클라우드 가상 자산 누락**
   - VM 인스턴스, 컨테이너 이미지, PVC 등 클라우드 자산이 자산 대장에 포함되지 않은 사례 빈번
   - k3s 환경의 경우 `kubectl get nodes,pv,pvc -A` 출력을 증적 첨부 권장
