## 분야 개요

서비스 공급망 관리는 클라우드 서비스를 구성하는 **외부 공급업체(IaaS, 데이터센터, 오픈소스 라이브러리)의 보안 위험을 관리**하는 통제입니다. SaaS 사업자는 자체 서비스 보안뿐 아니라 의존하는 공급망 전체의 보안 수준을 보증해야 합니다.

**핵심 키워드**: 공급망 보안 정책, 외부 서비스 보안 평가, 계약 보안 조항, SBOM 관리

**연계 MTU**:
- MTU-C8 공급망 보안 (SBOM + Sigstore): [`08-infra/supply-chain/`](../../../08-infra/supply-chain/) (Phase 2)
- MTU-A1 AI 보안 게이트웨이: 외부 AI API 서비스 공급망 보안 관리

## CSAP-D05-01: 공급망 보안 정책

> **중요도**: 상 | **구분**: 필수

### 구현 목표

클라우드 서비스 공급망(IaaS, 데이터센터, 외부 서비스 등)에 대한 보안 관리 정책을 수립한다.

### 구현 방법

**단계 1: 공급망 식별**

현재 서비스를 구성하는 모든 외부 공급요소를 식별합니다:

| 공급 유형 | 예시 | 보안 관리 항목 |
|---------|------|-------------|
| IaaS/PaaS | 클라우드 인프라 사업자 | CSAP 인증 보유 여부, SLA, 데이터 저장 위치 |
| 데이터센터 | 호스팅 사업자 | 물리 보안, 이중화, 재해 복구 체계 |
| 오픈소스 | npm/pip 패키지 | SBOM, CVE 점검, 라이선스 호환성 |
| AI API | LLM 서비스 사업자 | N2SF 데이터 등급 준수, PII 마스킹, 전송 암호화 |
| CDN/DNS | 외부 네트워크 서비스 | 가용성 SLA, DDoS 방어 능력 |

**단계 2: 공급망 보안 정책서 작성**

정책서에 포함해야 할 필수 항목:

| 섹션 | 필수 내용 |
|------|---------|
| 목적 | 공급망 보안 관리의 목적과 적용 범위 |
| 대상 | 공급망 유형별 관리 대상 목록 |
| 보안 요건 | 공급업체 선정 시 보안 평가 기준 |
| SLA 기준 | 가용성, 보안사고 통보 시한, 데이터 보호 수준 |
| 점검 주기 | 정기 보안 점검 일정 (연 1회 이상) |
| 사고 대응 | 공급업체 보안 사고 시 통보/대응 절차 |
| 계약 해지 | 보안 위반 시 계약 해지 조건 |

**단계 3: 경영진 승인 및 공표**

- 정보보호위원회 검토 및 대표이사(기관장) 승인
- 공급업체에 보안 요건 통보

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 공급망 보안 정책서 | PDF/문서 | 문서관리시스템 |
| SLA 계약서 (보안 조항 포함) | 계약서 | 계약 관리 시스템 |
| 공급업체 목록 (보안 평가 결과 포함) | 표 | 공급망 관리 대장 |

## CSAP-D05-02: 외부 서비스 보안 관리

> **중요도**: 상 | **구분**: 필수

### 구현 목표

외부 클라우드/호스팅 서비스 이용 시 보안 평가를 수행하고 위험을 관리한다.

### 구현 방법

**단계 1: 외부 서비스 보안 평가 체크리스트**

신규 외부 서비스 도입 시 아래 항목을 평가합니다:

| 평가 영역 | 평가 항목 | 기준 |
|---------|---------|------|
| 인증 현황 | CSAP/ISMS-P/ISO27001 인증 보유 | CSAP 인증 필수 (공공기관) |
| 데이터 저장 | 국내 데이터센터 여부 | 국내 저장 필수 (CSAP-D13-01) |
| 암호화 | 전송/저장 암호화 수준 | TLS 1.3+, AES-256 이상 |
| 접근 통제 | 인증/인가 체계 | RBAC + MFA 지원 |
| 감사 로그 | 접근 이력 제공 여부 | 최소 1년 보관 |
| 사고 대응 | 보안 사고 통보 체계 | 4시간 이내 통보 |
| 데이터 반환 | 서비스 종료 시 데이터 반환/파기 | 반환 절차 명시 |

**단계 2: 위험 분석 보고서 작성**

| 위험 요소 | 평가 방법 | 대응 전략 |
|---------|---------|---------|
| 서비스 중단 | SLA 가용성 조항 확인 | 멀티 벤더 전략, 대체 서비스 확보 |
| 데이터 유출 | 암호화/접근통제 수준 평가 | 전송/저장 암호화 필수, 접근 제한 |
| 규제 위반 | CSAP/N2SF 준수 여부 확인 | 미인증 서비스 도입 금지 |
| 공급업체 파산 | 재무 건전성 확인 | 데이터 반환 조항, 에스크로 |

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 외부 서비스 보안 평가서 | 보고서 | 문서관리시스템 |
| 위험 분석 보고서 | 보고서 | 문서관리시스템 |
| 외부 서비스 인증서 사본 | 인증서 | 공급망 관리 대장 |

## CSAP-D05-03: 계약 보안 요건

> **중요도**: 중 | **구분**: 필수

### 구현 목표

외주/공급업체 계약 시 보안 요건을 명시하고 SLA에 보안 조항을 포함한다.

### 구현 방법

**단계 1: 계약 보안 조항 필수 항목**

| 조항 | 내용 | 근거 |
|------|------|------|
| 비밀유지 | 계약 기간 및 종료 후 비밀유지 의무 | 개인정보보호법 제29조 |
| 데이터 보호 | 데이터 암호화, 접근 통제, 국내 저장 의무 | CSAP-D09, D13-01 |
| 보안 사고 통보 | 보안 사고 발생 시 4시간 이내 통보 의무 | CSAP-D06-04 |
| 감사 권한 | 발주기관의 보안 감사 실시 권한 | CSAP-D13-06 |
| 서비스 수준 | 가용성 99.9%+, 장애 복구 RTO/RPO 명시 | CSAP-D07, D13-05 |
| 데이터 반환 | 계약 종료 시 데이터 반환 및 완전 파기 | CSAP-D13-02 |
| 보안 위반 책임 | 보안 위반 시 손해배상 및 계약 해지 조건 | 계약법 |
| 하도급 관리 | 재외주(하도급) 시 사전 승인 및 보안 요건 동일 적용 | CSAP-D05-01 |

**단계 2: SLA 보안 지표**

| 지표 | 기준값 | 측정 주기 |
|------|-------|---------|
| 서비스 가용성 | 99.9% 이상 | 월간 |
| 보안 사고 통보 시한 | 4시간 이내 | 사고 발생 시 |
| 보안 패치 적용 | 긴급 7일, 일반 30일 | 패치 발표 시 |
| 취약점 점검 | 분기 1회 이상 | 분기 |
| 데이터 백업 | 일 1회 이상, RPO 1시간 | 일간 |

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 계약서 (보안 조항 포함) | 계약서 | 계약 관리 시스템 |
| SLA 문서 | 부속 문서 | 계약 관리 시스템 |
| 보안 요건 체크리스트 (계약 시 사용) | 체크리스트 | 문서관리시스템 |

## CSAP-D05-04: 공급망 모니터링

> **중요도**: 중 | **구분**: 권고

### 구현 목표

공급업체의 보안 수준을 정기적으로 점검하고 보안 사고 시 통보 체계를 운영한다.

### 구현 방법

**단계 1: 정기 점검 프로세스**

```
분기별 공급망 보안 점검 프로세스:

1. 공급업체 목록 갱신
   └─ 신규/해지 공급업체 반영

2. 보안 수준 점검
   ├─ CSAP/ISMS-P 인증 유효성 확인
   ├─ SLA 준수율 확인 (가용성, 사고 통보)
   └─ 보안 사고 이력 확인

3. SBOM 업데이트 점검 (MTU-C8 연계)
   ├─ 오픈소스 패키지 CVE 점검
   ├─ 라이선스 변경 확인
   └─ 사용 중단(deprecated) 패키지 확인

4. 점검 보고서 작성 및 보고
```

**단계 2: SBOM 관리 (MTU-C8 연계)**

소프트웨어 공급망 보안의 핵심인 SBOM(Software Bill of Materials) 관리 절차:

| 단계 | 활동 | 도구 | 주기 |
|------|------|------|------|
| 생성 | 프로젝트 의존성 SBOM 자동 생성 | Syft, CycloneDX | 빌드 시 |
| 저장 | SBOM 아카이브 보관 | Harbor, Git | 릴리스 시 |
| 배포 | 이용기관에 SBOM 공유 | 포털/API | 릴리스 시 |
| 업데이트 | CVE 발표 시 영향 분석 | Grype, Trivy | 일간 자동 |

> 상세 SBOM 관리 절차: MTU-C8 [`08-infra/supply-chain/sbom-guide.md`](../../../08-infra/supply-chain/sbom-guide.md) (Phase 2)

**단계 3: 보안 사고 통보 체계**

```
공급업체 보안 사고 발생
    │
    ▼
공급업체 → SaaS 사업자 (4시간 이내 통보)
    │
    ├─ 사고 심각도 판단
    │   ├─ Critical: 즉시 CISO 보고 + KISA 신고
    │   ├─ High: 4시간 이내 경영진 보고
    │   └─ Medium/Low: 일간 보고
    │
    ├─ 영향 분석
    │   ├─ 해당 데이터 범위 확인
    │   ├─ 이용기관 영향 평가
    │   └─ 추가 피해 방지 조치
    │
    └─ 사후 조치
        ├─ 원인 분석 보고서 요구
        ├─ 재발 방지 대책 확인
        └─ SLA 위반 시 패널티 적용
```

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 공급업체 정기 점검 보고서 | 보고서 | 문서관리시스템 |
| SBOM 아카이브 | JSON/XML | Harbor/Git |
| 보안 사고 통보 절차서 | 절차서 | 문서관리시스템 |
| 보안 사고 통보 이력 | 기록 | 사고관리시스템 |
