## 분야 개요

재해 복구는 자연재해, 시스템 장애, 사이버 공격 등으로 인한 서비스 중단에 대비하여 **비즈니스 연속성을 보장**하는 운영/기술 통제입니다. 공공기관 SaaS는 행정 업무 연속성과 직결되므로 엄격한 RTO/RPO 목표와 정기 훈련이 필수입니다.

**핵심 키워드**: BCP/DRP, RTO/RPO, 백업/복구, 재해 복구 훈련

**연계 MTU**:
- MTU-I1 k3s WSL2 클러스터: 백업/복구 절차의 인프라 기반
- MTU-I3 Flux + Harbor: GitOps 기반 자동 복구 체계
- MTU-I5 N2SF 아키텍처: 재해 시 N2SF 등급별 복구 우선순위

## CSAP-D07-01: 서비스 연속성 계획

> **중요도**: 상 | **구분**: 필수

### 구현 목표

BCP(사업연속성계획)/DRP(재해복구계획) 문서를 수립하고 RTO/RPO 목표를 설정하며 경영진 승인을 받는다.

### 구현 방법

**단계 1: RTO/RPO 목표 설정**

| 지표 | 정의 | 목표값 | 근거 |
|------|------|-------|------|
| **RTO** (Recovery Time Objective) | 서비스 복구까지 허용되는 최대 시간 | **4시간 이내** | CSAP-D13-05 SLA 99.9% + 공공기관 행정 연속성 |
| **RPO** (Recovery Point Objective) | 데이터 손실이 허용되는 최대 시간 | **1시간 이내** | 공공 행정 데이터 무결성 기준 |

**단계 2: 재해 유형별 대응 전략**

| 재해 유형 | 예시 | 대응 전략 | 예상 복구 시간 |
|---------|------|---------|-------------|
| 시스템 장애 | 서버 다운, 디스크 장애 | k3s 자동 재스케줄링, PV 복구 | 30분 이내 |
| 네트워크 장애 | 네트워크 단절, DNS 장애 | 이중화 네트워크 전환, DNS 페일오버 | 1시간 이내 |
| 사이버 공격 | 랜섬웨어, DDoS | 네트워크 격리 + 백업 복구 | 4시간 이내 |
| 데이터센터 장애 | 전력 중단, 자연재해 | DR 사이트 전환 (해당 시) | 4시간 이내 |
| 소프트웨어 장애 | 배포 실패, 치명적 버그 | 롤백 (GitOps Flux 자동) | 15분 이내 |

**단계 3: BCP/DRP 문서 구성**

| 섹션 | 필수 내용 |
|------|---------|
| 목적 및 범위 | BCP/DRP 적용 대상 서비스 및 시스템 |
| RTO/RPO 목표 | 서비스별 복구 목표 시간 및 데이터 손실 허용 |
| 재해 유형 분류 | 자연재해, 시스템 장애, 사이버 공격, 인적 오류 |
| 복구 우선순위 | 업무 영향 분석(BIA) 기반 복구 순서 |
| 복구 절차 | 재해 유형별 단계별 복구 절차 (체크리스트 형태) |
| 비상 연락망 | 재해 시 연락 체계 및 역할 분담 |
| 훈련 계획 | 연 1회 이상 재해 복구 훈련 일정 |
| 문서 관리 | 연 1회 검토 및 갱신, 변경 이력 관리 |

**단계 4: 경영진 승인**

- 정보보호위원회에서 BCP/DRP 검토
- 대표이사(기관장) 승인 (서명)
- 승인 후 이용기관에 BCP/DRP 요약본 공유

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| BCP/DRP 문서 (승인본) | PDF/문서 | 문서관리시스템 |
| RTO/RPO 목표서 | 표 | BCP/DRP 내 섹션 |
| 업무 영향 분석(BIA) 결과 | 보고서 | 문서관리시스템 |
| 경영진 승인 이력 | 서명/승인 문서 | 승인 서류함 |

## CSAP-D07-02: 백업 및 복구

> **중요도**: 상 | **구분**: 기술(필수)

### 구현 목표

정기 백업을 수행하고 복구 테스트를 실시하며 백업 데이터의 무결성을 검증한다.

### 구현 방법

**단계 1: 백업 정책**

| 항목 | 정책 | 근거 |
|------|------|------|
| 전체 백업 | 주 1회 (일요일 02:00) | RPO 1시간 보완 |
| 증분 백업 | 일 1회 (매일 02:00) | 일반 데이터 보호 |
| 실시간 백업 | WAL/binlog 아카이빙 (연속) | RPO 1시간 달성 |
| 보관 기간 | 전체 백업 90일, 증분 30일, WAL 7일 | 저장 공간 최적화 |
| 암호화 | AES-256 암호화 후 저장 | CSAP-D09-02 |
| 검증 | 월 1회 무결성 체크섬 검증 | 데이터 무결성 보장 |

**단계 2: k3s 환경 백업 대상 및 방법**

| 백업 대상 | 백업 방법 | 도구 | 주기 |
|---------|---------|------|------|
| etcd (클러스터 상태) | 스냅샷 | `k3s etcd-snapshot save` | 일 1회 |
| PersistentVolume (데이터) | 볼륨 스냅샷 | Velero, Restic | 일 1회 |
| 데이터베이스 | 논리적 덤프 + WAL | pg_dump + WAL 아카이빙 | 일 1회 + 연속 |
| 설정 파일 (ConfigMap, Secret) | Git 저장소 | Flux GitOps | 변경 시 자동 |
| audit.jsonl (감사 로그) | 파일 백업 | rsync, rclone | 일 1회 |

**k3s etcd 스냅샷 백업 예시**:

```bash
#!/bin/bash
# k3s etcd 스냅샷 백업 스크립트
# 실행 주기: 일 1회 (cron: 0 2 * * *)

BACKUP_DIR="/backup/etcd"
DATE=$(date +%Y%m%d_%H%M%S)
RETENTION_DAYS=30

# etcd 스냅샷 생성
k3s etcd-snapshot save --name "daily-${DATE}"

# 로컬 백업 디렉토리로 복사
cp /var/lib/rancher/k3s/server/db/snapshots/daily-${DATE} \
   "${BACKUP_DIR}/etcd-${DATE}.db"

# AES-256 암호화 (CSAP-D09)
openssl enc -aes-256-cbc -salt -pbkdf2 \
  -in "${BACKUP_DIR}/etcd-${DATE}.db" \
  -out "${BACKUP_DIR}/etcd-${DATE}.db.enc" \
  -pass env:BACKUP_ENCRYPTION_KEY

# 평문 백업 삭제
rm "${BACKUP_DIR}/etcd-${DATE}.db"

# SHA-256 체크섬 생성
sha256sum "${BACKUP_DIR}/etcd-${DATE}.db.enc" \
  > "${BACKUP_DIR}/etcd-${DATE}.db.enc.sha256"

# 보관 기간 초과 파일 정리
find "${BACKUP_DIR}" -name "etcd-*.db.enc" -mtime +${RETENTION_DAYS} -delete
find "${BACKUP_DIR}" -name "etcd-*.db.enc.sha256" -mtime +${RETENTION_DAYS} -delete

echo "[$(date)] etcd 백업 완료: etcd-${DATE}.db.enc"
```

**단계 3: 복구 테스트**

| 테스트 유형 | 방법 | 주기 | 성공 기준 |
|---------|------|------|---------|
| 전체 복구 테스트 | 백업에서 전체 클러스터 복원 | 분기 1회 | RTO 4시간 이내 완전 복구 |
| 데이터 복구 테스트 | DB 백업에서 특정 시점 복원 | 월 1회 | RPO 1시간 이내 데이터 복원 |
| 파일 복구 테스트 | 개별 파일/설정 복원 | 월 1회 | 요청 파일 정확히 복원 |
| 무결성 검증 | 체크섬 비교 | 월 1회 | 백업 데이터 손상 0건 |

**복구 테스트 절차**:

```
1. 테스트 환경 준비
   └─ 별도 네임스페이스 또는 테스트 클러스터 구성

2. 백업 데이터 복원
   ├─ etcd 스냅샷 복원: k3s server --cluster-reset --cluster-reset-restore-path=<snapshot>
   ├─ PV 복원: velero restore create --from-backup <backup-name>
   └─ DB 복원: pg_restore + WAL replay (특정 시점)

3. 복원 결과 검증
   ├─ 서비스 정상 동작 확인
   ├─ 데이터 정합성 확인 (레코드 수, 체크섬)
   └─ 복원 시간 기록 (RTO 확인)

4. 테스트 결과 보고서 작성
```

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 백업 정책서 | PDF/문서 | 문서관리시스템 |
| 백업 실행 로그 (자동 백업 증빙) | 로그/스크린샷 | 서버 관리 시스템 |
| 복구 테스트 결과 보고서 | 보고서 | 문서관리시스템 |
| 백업 체크섬 검증 결과 | 검증 기록 | 서버 관리 시스템 |
| Velero/cron 설정 증빙 | 설정 파일 | 인프라 관리 |

## CSAP-D07-03: 재해 복구 훈련

> **중요도**: 중 | **구분**: 필수

### 구현 목표

연 1회 이상 재해 복구 훈련을 실시하고 훈련 결과를 분석하여 개선한다.

### 구현 방법

**단계 1: 훈련 계획 수립**

| 항목 | 내용 |
|------|------|
| 훈련 주기 | 연 1회 이상 (반기 1회 권장) |
| 훈련 유형 | 탁상 훈련(TTX), 기능 훈련, 전체 훈련 |
| 참여 인원 | CSIRT, 시스템 운영팀, 경영진 (역할별) |
| 훈련 시나리오 | 재해 유형별 시나리오 (2개 이상) |
| 성공 기준 | RTO 4시간 이내 복구, RPO 1시간 이내 데이터 |

**단계 2: 훈련 유형별 상세**

| 훈련 유형 | 설명 | 소요 시간 | 대상 |
|---------|------|---------|------|
| 탁상 훈련 (TTX) | 시나리오 기반 토론 형태, 절차 숙지 | 2~4시간 | 전체 관련 인원 |
| 기능 훈련 | 실제 백업 복구 실행, 특정 기능 검증 | 4~8시간 | 기술 운영팀 |
| 전체 훈련 | 실제 재해 상황 시뮬레이션, 전 과정 실행 | 8~16시간 | 전 조직 |

**단계 3: 훈련 시나리오 예시**

**시나리오 A: 랜섬웨어 감염**

```
상황: 운영 서버 랜섬웨어 감염 → 데이터 암호화 → 서비스 중단

훈련 단계:
1. 탐지: 보안 모니터링 시스템에서 이상 탐지 (audit.jsonl 비정상 패턴)
2. 격리: 감염 서버 네트워크 격리 (k3s 노드 cordon)
3. 분석: 감염 범위 확인, 백업 데이터 무결성 확인
4. 복구: 
   - etcd 스냅샷에서 클러스터 상태 복원
   - Velero에서 PV 데이터 복원
   - DB WAL 아카이브에서 특정 시점 복원
5. 검증: 서비스 정상 동작, 데이터 정합성 확인
6. 보고: KISA 신고, 이용기관 통보

성공 기준: 4시간 이내 서비스 복구, 1시간 이내 데이터 복원
```

**시나리오 B: 데이터센터 전력 장애**

```
상황: 주 데이터센터 전력 공급 장애 → 전체 시스템 셧다운

훈련 단계:
1. 탐지: 모니터링 시스템 알림 (서비스 불가)
2. 전환: DR 사이트(또는 대체 인프라)로 서비스 전환
3. 복구: 
   - DNS 전환 (DR 사이트로)
   - 최신 백업에서 데이터 복원
   - 서비스 기동 및 헬스체크
4. 검증: 이용자 접근 가능 확인, 데이터 정합성 확인
5. 보고: 이용기관 통보, 장애 보고서 작성

성공 기준: 4시간 이내 서비스 재개
```

**단계 4: 훈련 결과 분석 및 개선**

| 분석 항목 | 확인 사항 |
|---------|---------|
| 복구 시간 | 실제 복구 시간 vs RTO 목표 (4시간) |
| 데이터 복원 | 실제 데이터 손실 vs RPO 목표 (1시간) |
| 절차 준수 | BCP/DRP 절차 준수 여부 |
| 비상 연락 | 비상 연락망 정상 작동 여부 |
| 역할 수행 | 각 담당자 역할 수행 적정성 |
| 도구/시스템 | 백업/복구 도구 정상 동작 여부 |
| 개선 사항 | 절차 보완, 도구 추가, 교육 필요 사항 |

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 훈련 계획서 | PDF/문서 | 문서관리시스템 |
| 훈련 실행 기록 (타임라인, 스크린샷) | 기록/사진 | 문서관리시스템 |
| 훈련 결과 분석 보고서 | 보고서 | 문서관리시스템 |
| 개선 조치 이행 점검표 | 체크리스트 | 문서관리시스템 |
