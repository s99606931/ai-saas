## 분야 개요

공공기관 추가 보호조치는 **공공기관 전용 SaaS에 적용되는 강화된 보안 요건**입니다. 일반 CSAP 요건에 더해 국내 데이터 저장, 데이터 주권, N2SF 등급 분류, 공공기관 전용 영역 분리, SLA 등의 추가 통제를 요구합니다.

**핵심 키워드**: 국내 데이터 저장, 데이터 주권, N2SF 등급, 공공기관 전용 영역, SLA, 감사 추적 강화

**연계 MTU**:
- MTU-C4 N2SF 매핑: 데이터 등급 분류(C/S/O) 상세
- MTU-C8 공급망 보안: Harbor + Cosign 이미지 서명
- MTU-I2 Gitea CI/CD: 파이프라인 보안 통합

## CSAP-D13-01: 국내 데이터 저장

> **중요도**: 상 | **구분**: 필수

### 구현 목표

공공기관 데이터가 국내 데이터센터에만 저장됨을 보장하고 해외 전송을 차단한다.

### 구현 방법

| 항목 | 구현 |
|------|------|
| 데이터센터 위치 | 국내 데이터센터만 사용 (해외 금지) |
| CDN | 국내 CDN만 사용, 해외 미러링 금지 |
| 백업 | 국내 데이터센터 내 백업 (해외 복제 금지) |
| DNS | 국내 DNS 서버 사용 |
| 클라우드 리전 | 국내 리전만 선택 가능 (설정으로 강제) |

**네트워크 레벨 해외 전송 차단**

```yaml
# k3s Egress 정책: 국내 IP 대역만 허용 (예시)
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: restrict-international-egress
  namespace: production
spec:
  podSelector: {}
  egress:
    - to:
        - ipBlock:
            cidr: 0.0.0.0/0
            except:
              # 해외 IP 대역 차단은 실무적으로 방화벽/프록시에서 처리
              # 여기서는 허용된 국내 서비스 IP만 명시
        - podSelector: {}  # 내부 통신
  policyTypes:
    - Egress
```

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 데이터센터 위치 증명서 | 증명서 | 문서관리시스템 |
| 데이터 저장 정책서 | PDF/문서 | 문서관리시스템 |
| 네트워크 설정 (해외 차단) | 방화벽 규칙 | 네트워크 관리 |

## CSAP-D13-02: 데이터 주권 보장

> **중요도**: 상 | **구분**: 필수

### 구현 목표

데이터 소유권이 이용기관에 있음을 계약에 명시하고 서비스 종료 시 데이터 반환/파기 절차를 수립한다.

### 구현 방법

**계약서 필수 조항**

| 조항 | 내용 |
|------|------|
| 데이터 소유권 | 데이터의 소유권은 이용기관에 귀속됨을 명시 |
| 데이터 접근 | SaaS 사업자의 고객 데이터 접근 범위 제한 및 승인 절차 |
| 데이터 반환 | 계약 종료 시 표준 형식(JSON/CSV/DB 덤프)으로 데이터 반환 |
| 데이터 파기 | 반환 완료 후 30일 이내 완전 파기 (복구 불가 방식) |
| 파기 증명 | 데이터 파기 완료 증명서 발급 |

**데이터 반환/파기 절차**

```
계약 종료 통보 (30일 전)
    │
    ▼
데이터 반환 준비 (7일)
    ├─ 데이터 추출 (표준 형식)
    ├─ 무결성 검증 (체크섬)
    └─ 반환 매체 암호화
    │
    ▼
데이터 전달 및 확인 (7일)
    ├─ 이용기관 데이터 수신 확인
    └─ 무결성 검증 완료 확인
    │
    ▼
데이터 완전 파기 (반환 확인 후 30일)
    ├─ DB 레코드 삭제 + 오버라이트
    ├─ 백업 데이터 삭제
    ├─ 스토리지 제로화
    └─ 파기 증명서 발급
```

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 서비스 계약서 (데이터 조항) | 계약서 | 계약 관리 시스템 |
| 데이터 반환 절차서 | PDF/문서 | 문서관리시스템 |

## CSAP-D13-03: N2SF 데이터 등급 분류

> **중요도**: 상 | **구분**: 필수

### 구현 목표

처리 데이터의 N2SF 등급(C/S/O)을 분류하고 등급별 처리 기준을 수립한다.

### 구현 방법

> 상세 등급 분류 체계: MTU-C4 [`04-n2sf/data-grade-classification.md`](../../04-n2sf/data-grade-classification.md)

| 등급 | 분류 기준 | AI API | 저장 | 전송 |
|------|---------|--------|------|------|
| C (기밀) | 국가 안보, 핵심 개인정보 | **금지** | AES-256 필수 | mTLS 필수 |
| S (민감) | 내부 업무, 인사, 예산 | **금지** | AES-256 필수 | TLS 1.3 필수 |
| O (공개) | 공개 가능 일반 정보 | PII 마스킹 후 허용 | 권장 | TLS 1.3 필수 |

```typescript
// N2SF 데이터 등급 통제 (CSAP-D13-03 + MTU-C4)
enum DataGrade { C = 'C', S = 'S', O = 'O' }

function classifyData(dataType: string): DataGrade {
  const classificationMap: Record<string, DataGrade> = {
    'personal_info_ssn': DataGrade.C,     // 주민등록번호
    'personal_info_health': DataGrade.C,  // 건강 정보
    'budget_data': DataGrade.S,           // 예산 정보
    'hr_data': DataGrade.S,               // 인사 정보
    'public_notice': DataGrade.O,         // 공고문
    'service_guide': DataGrade.O,         // 서비스 안내
  }
  return classificationMap[dataType] ?? DataGrade.S  // 기본: 민감 처리
}
```

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 데이터 등급 분류표 | 표 | 문서관리시스템 |
| 등급별 처리 기준서 | PDF/문서 | 문서관리시스템 |
| 등급 분류 코드 | 소스코드 | Git 저장소 |

### 구현 방법

```yaml

kind: Namespace
metadata:
  name: gov-production
  labels:
    tier: government
    pod-security.kubernetes.io/enforce: restricted

---
# 공공기관 전용 노드 라벨
# kubectl label nodes gov-node-1 tier=government

# Pod에 노드 어피니티 적용 (공공기관 전용 노드만)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: gov-app
  namespace: gov-production
spec:
  template:
    spec:
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
              - matchExpressions:
                  - key: tier
                    operator: In
                    values:
                      - government
```

## CSAP-D13-06: 감사 추적 강화

> **중요도**: 상 | **구분**: 필수

### 구현 목표

모든 민감 작업의 감사 로그를 append-only로 보장하고 감리기관 열람을 지원한다.

### 구현 방법

ECC 하네스의 `audit.jsonl`이 이 요건의 핵심 구현입니다:

| 항목 | 구현 |
|------|------|
| 기록 대상 | 인증/인가, CRUD, 설정 변경, 데이터 반출 등 전수 |
| 무결성 | append-only (chattr +a), 해시 체인 |
| 보관 기간 | 최소 1년 (CSAP-D06-03) |
| 열람 지원 | 감리기관 전용 읽기 전용 접근 권한 |
| 포맷 | JSON Lines (기계 판독 가능) |

```typescript
// 감리기관 열람 API (읽기 전용)
export async function GET(req: Request) {
  const user = await verifyToken(req.headers.get('authorization'))

  // 감리기관 전용 역할 확인
  if (!hasPermission(user, 'audit:read')) {
    return Response.json({ error: 'Forbidden' }, { status: 403 })
  }

  // 날짜 범위 필터
  const { startDate, endDate } = parseQuery(req.url)
  const logs = await readAuditLogs(startDate, endDate)

  await auditLog({
    actor: user.id,
    action: 'AUDIT_LOG_VIEW',
    target: `${startDate}~${endDate}`,
    result: 'success',
    ip: getClientIP(req),
    metadata: { role: 'auditor', recordCount: logs.length }
  })

  return Response.json({ data: logs })
}
```

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 감사 로그 시스템 구성 | 설정/코드 | Git 저장소 |
| 무결성 검증 설정 (append-only) | 설정 증빙 | 인프라 관리 |
| 감리기관 열람 지원 절차 | 문서 | 문서관리시스템 |

## CSAP-D13-09: 물리적 보안

> **중요도**: 상 | **구분**: 필수

### 구현 목표

데이터센터 물리적 접근을 통제하고 환경(온습도, 전력)을 관리한다.

### 구현 방법

| 항목 | 구현 |
|------|------|
| 출입 통제 | 카드키/생체 인증 (2팩터) |
| 출입 기록 | 전수 기록 + 6개월 보관 |
| CCTV | 주요 구역 24시간 녹화 + 30일 보관 |
| 환경 관리 | 온도 20-25도, 습도 40-60% |
| 전력 | UPS + 비상 발전기 (최소 4시간) |
| 소화 | 가스 소화 설비 (전산실) |

> 참고: WSL2 개발 환경에서는 물리적 보안이 직접 적용되지 않습니다. 이 항목은 운영 데이터센터에 적용합니다.

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 출입 기록 | 전자 기록 | 출입 관리 시스템 |
| CCTV 운영 현황 | 운영 기록 | 물리 보안 시스템 |

## CSAP-D13-10: 클라우드 서비스 투명성

> **중요도**: 중 | **구분**: 필수

### 구현 목표

서비스 아키텍처, 보안 조치, 데이터 처리 절차를 이용기관에 투명하게 공개한다.

### 구현 방법

**투명성 보고서 포함 항목**

| 섹션 | 내용 |
|------|------|
| 서비스 아키텍처 | 시스템 구성도, 데이터 흐름도 |
| 보안 조치 | CSAP 인증 현황, 적용 보안 통제 요약 |
| 데이터 처리 | 데이터 저장 위치, 암호화 방법, 접근 통제 |
| SLA 이행 현황 | 가용성 실적, 보안 사고 이력, 패치 현황 |
| 제3자 감사 | 외부 감사 결과 요약 (해당 시) |
| 연락처 | 보안 담당자 연락처, 사고 신고 채널 |

### 필요 증거 자료

| 증거 | 형태 | 보관 위치 |
|------|------|---------|
| 서비스 보안 백서 | PDF/문서 | 공개 포털 |
| 아키텍처 문서 | 기술 문서 | 이용기관 전용 포털 |
