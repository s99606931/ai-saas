## 2. Context Anchor

### WHY (왜 필요한가)

17개 마이크로서비스와 22개 공유 패키지로 구성된 대규모 모노레포에서 일관된 코딩 패턴과 기술 스택 표준이 없으면 다음 문제가 발생한다:

1. 서비스 간 구현 패턴 불일치로 유지보수 비용 증가
2. 신규 개발자 온보딩 시 참조할 표준 문서 부재
3. CSAP/N2SF 보안 요건을 개별 서비스에서 반복 구현
4. 행안부 감리 시 일관된 기술 기준 증빙 미비

### WHO (이해관계자)

| 역할 | 관심사 |
|------|-------|
| 개발팀 | 명확한 코딩 표준, 패턴 레퍼런스 |
| 감리관 | 기술 기준 문서, 추적성 매트릭스 |
| 보안 담당 | CSAP/N2SF 준수 코딩 패턴 |
| PM | 기술 부채 관리, 일관성 확보 |

### RISK (위험 요소)

| ID | 위험 | 영향 | 대응 |
|----|------|------|------|
| R1 | 지침서가 실제 코드와 괴리 | 개발자 미준수 | 실제 코드에서 패턴 추출 |
| R2 | 과도한 표준화로 유연성 저하 | 개발 속도 감소 | 필수/권장/선택 등급 구분 |
| R3 | 기술 스택 버전 호환성 이슈 | 빌드 실패 | 검증된 버전 매트릭스 제공 |

### SUCCESS (성공 기준)

| ID | 기준 | 측정 방법 |
|----|------|----------|
| SC-1 | 지침서 3종 (코딩/디자인/문서) 작성 완료 | 파일 존재 확인 |
| SC-2 | 기술 스택 버전 매트릭스 확정 | Design 문서 내 테이블 |
| SC-3 | CSAP 준수 코딩 패턴 10개 이상 문서화 | 지침서 패턴 카운트 |
| SC-4 | 현재 코드베이스와 불일치 항목 목록화 | 분석 결과 문서 |

### SCOPE (범위)

**포함**: 기술 스택 버전 확정, 코딩 표준, 디자인 패턴, 문서 작성 표준
**제외**: 실제 코드 리팩토링 (별도 MTU로 진행), 인프라 변경, CI/CD 파이프라인 수정

## 3. 기능 요구사항

### CC-REQ-01: 기술 스택 버전 매트릭스

프로젝트에서 사용하는 모든 기술의 확정 버전을 단일 테이블로 관리한다.

- 런타임, 언어, 프레임워크, ORM, 테스트, 보안 도구 포함
- 각 기술의 최소/권장/최대 버전 명시
- pnpm workspace 호환성 검증 결과 포함

### CC-REQ-02: TypeScript 코딩 표준

프로젝트 전체에 적용되는 TypeScript 코딩 규칙을 문서화한다.

- strict 모드 설정 (noUnusedLocals, noUncheckedIndexedAccess 포함)
- 타입 정의 패턴 (@public-saas/types 중앙화)
- Zod 스키마 검증 표준 패턴
- 비동기 처리 패턴 (async/await, 에러 처리)
- 네이밍 규칙 (파일, 변수, 함수, 타입)

### CC-REQ-03: Fastify 서비스 패턴

Fastify 기반 마이크로서비스의 표준 구조와 패턴을 정의한다.

- 서비스 진입점 (index.ts) 표준 구조
- 플러그인 등록 순서 (설정 -> 인프라 -> 보안 -> 비즈니스)
- 라우트 등록 패턴 (JSON Schema + preHandler)
- 핸들러 패턴 (검증 -> 비즈니스 -> 응답)

### CC-REQ-04: 프론트엔드 패턴

Next.js 15 App Router 기반 프론트엔드 표준 패턴을 정의한다.

- Server Component / Client Component 구분 기준
- 레이아웃 구성 패턴 (AppShell, Sidebar, Navbar)
- 보안 헤더 미들웨어 (CSP nonce)
- 상태 관리 전략

### CC-REQ-05: 공유 패키지 패턴

@public-saas/* 공유 패키지의 표준 구조와 export 패턴을 정의한다.

- 패키지 엔트리포인트 (index.ts) 구조
- Fastify 플러그인 래핑 패턴 (fastify-plugin)
- 타입 export 패턴 (type 키워드 필수)
- 패키지 간 의존성 규칙

### CC-REQ-06: 보안 코딩 패턴

CSAP/N2SF 요건을 만족하는 코딩 패턴을 표준화한다.

- RBAC 적용 패턴 (D-08)
- 감사 로그 기록 패턴 (D-06)
- 입력 검증 패턴 (D-12)
- 데이터 등급 검증 패턴 (N2SF N-05)
- PII 마스킹 패턴
- 암호화 패턴 (D-09)

### CC-REQ-07: 디자인 패턴 표준

백엔드/프론트엔드에서 사용하는 디자인 패턴을 분류하고 문서화한다.

- Repository 패턴 (DB 접근 추상화)
- Service Layer 패턴 (비즈니스 로직 격리)
- Plugin 패턴 (Fastify 확장)
- 멀티테넌시 패턴 (Row-Level Security, 테넌트 컨텍스트)
- 이벤트 버스 패턴 (비동기 도메인 이벤트)

### CC-REQ-08: 문서 작성 표준

모든 PDCA 문서의 작성 형식을 표준화한다.

- Plan 문서 필수 섹션 및 ID 체계
- Design 문서 필수 섹션 및 다이어그램 표준
- 코드 주석 표준 (Design Ref, Plan SC, CSAP)
- 변경 이력 형식
