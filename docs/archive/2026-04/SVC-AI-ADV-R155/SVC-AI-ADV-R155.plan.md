## Context Anchor

- **WHY**: 공공기관은 수십 개 데이터 포털 API를 개별 연동 — 표준 브릿지로 통합 비용 절감
- **WHO**: 데이터 통합 담당자, 빅데이터 분석가
- **RISK**: API 응답 구조 변경 → 스키마 버전 관리; 네트워크 오류 → 재시도 정책
- **SUCCESS**: 엔드포인트 등록 → 호출 → 응답 정규화 → 매핑 결과 반환
- **SCOPE**: In — 엔드포인트 등록/호출/정규화. Out — 실시간 data.go.kr 인증

## 요구사항

- **FR-R155.1**: 공공 API 엔드포인트 등록 (id, url, schema mapping)
- **FR-R155.2**: 데이터 패치 (주입 가능한 fetchFn)
- **FR-R155.3**: 응답 정규화 — 필드 매핑 + 타입 변환
- **FR-R155.4**: 에러 핸들링 — 재시도 N회, 타임아웃
- **FR-R155.5**: N2SF guard, PII 마스킹, 감사 로그
- **NFR-R155.1**: TypeScript strict, 테스트 5개+
