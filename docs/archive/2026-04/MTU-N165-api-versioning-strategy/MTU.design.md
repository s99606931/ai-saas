# MTU-N165: API 버전 관리 전략 — Design

> **버전**: 1.0.0 | **작성일**: 2026-04-10 | **작성자**: PM Lead

---

## 1. Design Anchor

| 항목 | 결정 |
|------|------|
| 버전 체계 | URI 경로 기반 (v1, v2), Semantic Versioning |
| 하위호환 | 최소 2개 메이저 버전 동시 운영 |
| Deprecation | 신버전 출시 후 6개월간 이전 버전 유지 |
| 호환성 검사 | OpenAPI diff 기반 CI/CD 자동 검사 |

---

## 2. 버전 관리 정책

### 2.1 변경 유형 분류

| 유형 | 설명 | 버전 영향 | 예시 |
|------|------|---------|------|
| 파괴적 변경 | 기존 API 제거/변경 | 메이저 +1 | 필드 삭제, 타입 변경 |
| 하위호환 추가 | 새 필드/엔드포인트 | 마이너 +1 | 선택적 필드 추가 |
| 버그 수정 | 동작 수정 | 패치 +1 | 응답 오류 수정 |

### 2.2 Deprecation 프로세스

```
1. 신버전 출시 → 이전 버전에 Deprecation 헤더 추가
2. +3개월: 이전 버전 사용 시 경고 로그
3. +6개월: 이전 버전 종료 (404 반환)
```
