# PRD: auth-service 라운드 1 고도화

> MTU ID: SVC-AUTH-R1
> 버전: 1.0.0 | 작성일: 2026-04-09

---

## WHY — 왜 필요한가

auth-service는 공공기관 SaaS 플랫폼의 핵심 보안 서비스입니다. 현재 구현은 CSAP D-08 접근 통제의 기본 요건을 충족하나, 다음 영역에서 보안 강화가 필수적입니다:

1. MFA 활성 사용자 로그인 시 TOTP 검증이 누락되어 MFA 우회 가능
2. 비밀번호 변경 API가 없어 사용자 자율 비밀번호 관리 불가
3. 로그인 엔드포인트에 Rate Limiting이 없어 무차별 대입 공격 취약
4. 내부 서비스 간 통신에 인증이 없어 CSAP D-08 위반 가능
5. OpenTelemetry 계측이 없어 보안 사고 시 분산 추적 불가

## WHO — 이해관계자

| 역할 | 관심사 |
|------|--------|
| 보안 감리관 | CSAP D-08 접근 통제 완전 준수 여부 |
| 테넌트 관리자 | MFA 강제 적용, 비밀번호 정책 관리 |
| 일반 사용자 | 안전한 로그인, 비밀번호 변경 기능 |
| 플랫폼 운영자 | 보안 모니터링, 분산 추적 |
| 개발자 | API 명세 완전성, 테스트 커버리지 |

## RISK — 위험 요소

| 위험 | 영향 | 완화 방안 |
|------|------|-----------|
| MFA 우회 | 2차 인증 무력화 | 로그인 흐름에 MFA 검증 단계 추가 |
| 무차별 대입 공격 | 계정 탈취 | IP 기반 Rate Limiting + 계정 잠금 강화 |
| 내부 서비스 위장 | 세션 무효화 API 오용 | 서비스 간 인증 토큰 도입 |
| 키 유출 | 전체 JWT 위조 가능 | JWK 키 회전 + kid 헤더 도입 |

## SUCCESS — 성공 기준

| ID | 기준 | 측정 방법 |
|----|------|-----------|
| SC-1 | MFA 활성 사용자 로그인 시 TOTP 검증 통과 필수 | 통합 테스트 |
| SC-2 | 비밀번호 변경 API 동작 (현재 + 정책 검증 + 세션 무효화) | 통합 테스트 |
| SC-3 | 로그인 Rate Limiting (IP당 60초 10회) | 부하 테스트 |
| SC-4 | 내부 서비스 API에 서비스 토큰 인증 적용 | 통합 테스트 |
| SC-5 | OpenTelemetry 트레이스 내보내기 동작 | 로그 확인 |
| SC-6 | JWT kid 헤더 포함 + 키 회전 지원 구조 | 단위 테스트 |
| SC-7 | 테스트 커버리지 80% 이상 | vitest coverage |

## SCOPE — 범위

### 포함 (In Scope)

1. 로그인 핸들러 MFA 검증 단계 추가
2. POST /auth/password/change 엔드포인트 추가
3. IP 기반 Rate Limiting 미들웨어 (Redis 기반)
4. 서비스 간 인증 미들웨어 (X-Service-Token)
5. JWT kid 헤더 + 키 회전 지원 구조
6. OpenTelemetry 계측 (HTTP span, DB span)
7. HTTP 수준 통합 테스트 추가

### 제외 (Out of Scope)

1. SSO/SAML/OIDC 연동 (라운드 2)
2. 비밀번호 이력 관리 (라운드 2)
3. 디바이스 핑거프린팅 (라운드 3)
4. 웹훅 기반 이벤트 발행 (라운드 2)
