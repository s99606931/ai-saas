# 공공기관 SaaS 프레임워크 PRD (Product Requirements Document)

> **Feature**: public-saas-framework
> **Date**: 2026-04-05
> **Status**: Draft
> **Author**: PM Agent Team (pm-lead)

---

## Executive Summary

| 관점 | 내용 |
|------|------|
| **문제** | 중소 IT 기업이 공공기관 SaaS 시장에 진입하려면 CSAP 인증, 감리 산출물, 보안통제 등 높은 규제 장벽을 넘어야 하며, 이 과정에서 6~12개월의 준비 기간과 수억 원의 비용이 소요된다 |
| **솔루션** | CSAP/N2SF 보안통제 템플릿, 감리 산출물 자동 생성 가이드, k3s 기반 배포 레시피, AI 연동 프레임워크를 표준화된 패키지로 제공하여 공공 SaaS 진입 비용을 70% 이상 절감한다 |
| **기능/UX 효과** | 비즈니스 도메인만 결정하면 프레임워크 위에서 즉시 개발 착수 가능. 감리 체크리스트 자동 매핑, 보안통제 항목 자동 적용으로 규제 준수 부담 최소화 |
| **핵심 가치** | 공공기관 SaaS 시장의 민주화 -- 대기업만 접근 가능했던 공공 시장을 중소기업도 체계적으로 진입할 수 있도록 표준 프레임워크 제공 |

# Part 1: Discovery 분석

## 1. 5-Step Discovery Chain

### Step 1: 기회 브레인스토밍 (Opportunity Brainstorm)

공공기관 SaaS 프레임워크를 둘러싼 핵심 기회 영역:

| # | 기회 영역 | 설명 | 영향도 |
|---|-----------|------|--------|
| O1 | CSAP 인증 준비 자동화 | 보안통제 79개 항목(표준등급) 또는 31개 항목(간편등급)의 체크리스트 템플릿화 | 매우 높음 |
| O2 | 감리 산출물 표준화 | 계획서, 설계서, 시험결과서 등 감리 필수 산출물 템플릿 제공 | 높음 |
| O3 | N2SF 전환 대응 | 2026년 시행되는 국가망보안체계(N2SF) C/S/O 등급 분류 체계 선제 대응 | 매우 높음 |
| O4 | 온프레미스/k3s 배포 표준화 | WSL2/k3s 기반 경량 쿠버네티스 환경에서의 공공 SaaS 배포 레시피 | 중간 |
| O5 | AI/LLM 연동 가이드 | 공공기관 보안 요건 충족하면서 외부 AI API(Claude, GPT-4)를 안전하게 연동하는 패턴 | 높음 |
| O6 | 자립형 CI/CD 파이프라인 | Gitea + Gitea Actions 기반 외부 의존성 없는 CI/CD 구성 | 중간 |
| O7 | 공공 SaaS 마켓플레이스 진입 지원 | 정부 공공 SaaS 마켓플레이스 등록 프로세스 가이드 | 중간 |

| A2 | 표준화된 프레임워크가 있으면 CSAP 준비 기간을 6개월에서 2개월로 단축할 수 있다 | 가치 | 매우 높음 |
| A3 | 2026년 N2SF 시행으로 CSAP 없이도 공공 진출이 가능해지면서 시장 진입 기업이 증가한다 | 시장 | 높음 |
| A4 | k3s 기반 경량 환경이 공공기관 보안 요건을 충족할 수 있다 | 기술 | 중간 |

# Part 2: Strategy 분석

## 2. JTBD 6-Part Value Proposition

### 2.1 Job Statement

| 구성 요소 | 내용 |
|-----------|------|
| **When** | 중소 IT 기업이 공공기관 대상 SaaS 사업을 시작하려 할 때 |
| **I want to** | CSAP 인증, 감리 대응, 보안통제 적용을 체계적으로 준비하고 싶다 |
| **So I can** | 최소한의 시간과 비용으로 공공 시장에 진입하여 안정적 매출원을 확보하고 싶다 |

### 2.2 Functional Job

- 공공기관 보안 인증(CSAP/N2SF) 요건을 이해하고 충족한다
- 감리 체크리스트에 맞는 산출물을 생산한다
- 보안 요건을 만족하는 기술 아키텍처를 설계한다
- AI 서비스를 공공 보안 정책에 맞게 연동한다

### 2.3 Emotional Job

- 공공 시장 진입에 대한 불안감과 막막함을 해소한다
- "우리도 할 수 있다"는 자신감을 갖는다
- 규제 준수에 대한 확신을 갖고 사업에 집중한다

### 2.4 Social Job

- 공공기관 입찰 시 전문성 있는 기업으로 인식된다
- CSAP 인증 획득으로 신뢰도 있는 SaaS 제공자로 포지셔닝된다
- 공공 IT 생태계 내에서 인정받는 기업이 된다

### 2.5 Pain Points (현재 대안의 문제)

| # | Pain Point | 심각도 |
|---|-----------|--------|
| P1 | CSAP 인증 준비에 6~12개월 소요, 전담 인력 2~3명 필요 | 매우 높음 |
| P2 | 감리 산출물 형식/내용 기준이 불명확하여 반복 수정 | 높음 |
| P3 | 보안통제 79개 항목(표준등급)의 구체적 구현 방법 부재 | 매우 높음 |
| P4 | N2SF 전환으로 기존 CSAP 기준 변경 -- 혼란 가중 | 높음 |
| P5 | 공공 전용 기술 환경(폐쇄망, 온프레미스) 구축 노하우 부족 | 중간 |
| P6 | AI 서비스 연동 시 공공 데이터 보안 정책 충돌 우려 | 높음 |

### 2.6 Gain Creators (프레임워크 제공 가치)

| # | Gain | 기대 효과 |
|---|------|-----------|
| G1 | CSAP 준비 기간 70% 단축 | 6개월 -> 2개월 |
| G2 | 감리 1차 통과율 향상 | 50% -> 85% |
| G3 | 보안통제 구현 가이드로 기술 리스크 감소 | 보안 취약점 80% 사전 예방 |
| G4 | N2SF C/S/O 등급 자동 매핑으로 전환 비용 최소화 | 별도 컨설팅 비용 절감 |
| G5 | 표준 아키텍처로 개발 생산성 향상 | 개발 기간 40% 단축 |

## 4. SWOT 분석

| | 긍정적 | 부정적 |
|---|--------|--------|
| **내부** | **강점 (Strengths)** | **약점 (Weaknesses)** |
| | S1: k3s/Gitea 기반 완전 자립형 환경 (외부 의존성 제거) | W1: 아직 비즈니스 도메인 미정 (프레임워크만 선행) |
| | S2: CSAP + N2SF 동시 대응 설계 | W2: 소규모 팀으로 광범위한 규제 커버리지 한계 |
| | S3: AI 서비스 연동 가이드 포함 (차별화) | W3: 실제 CSAP 인증 획득 실적 없음 (검증 필요) |
| | S4: WSL2 로컬 환경에서 즉시 검증 가능 | W4: 공공기관 직접 레퍼런스 부재 |

| | O2: 정부 공공 SaaS 개발 지원사업 확대 (과기정통부) | T2: 대형 CSP(네이버, NHN 등)의 공공 SaaS 플랫폼 진출 |

| | O4: 공공기관 10,000개 시스템 클라우드 전환 의무화 | T4: 공공기관 보수적 기술 수용 문화 |

### SO 전략 (강점 x 기회)

- S2 x O1: N2SF 전환 시점에 맞춰 CSAP+N2SF 통합 프레임워크를 시장 최초 출시
- S3 x O4: 공공기관 클라우드 전환 시 AI 연동 가이드를 차별화 포인트로 활용
- S1 x O2: 자립형 환경 특성을 정부 지원사업과 연계하여 보안 우수성 어필

### WT 전략 (약점 x 위협)

- W1 x T1: 비즈니스 도메인 미정을 역으로 활용 -- N2SF 기준 확정 전까지 도메인 독립적 프레임워크에 집중
- W3 x T2: 대형 CSP와 경쟁 대신 "중소기업 전용 진입 도구"로 니치 포지셔닝
- W4 x T4: 파일럿 프로그램을 통해 1~2개 레퍼런스 확보 후 확대

| **Refactorer** | `refactor-cleaner` | **Haiku** | Dead code 0개 정책 |

**목표**: 동급 품질 대비 60% 비용 절감 (ECC Continuous Learning 패턴 재사용 효과 포함)

### A.4 Hooks 구성 (strict 프로필)

CSAP 중/상 등급 환경에는 `strict` 프로필을 사용하여 모든 훅을 활성화합니다.

```json
{
  "env": {
    "ECC_HOOK_PROFILE": "strict",
    "ECC_GOVERNANCE_CAPTURE": "1",
    "ENABLE_VERBOSE_LOGGING": "1"
  },
  "hooks": {
    "PreToolUse": [
      "pre:bash:block-no-verify",
      "pre:bash:git-push-reminder",
      "pre:write:doc-file-warning",
      "pre:config-protection",
      "pre:insaits:security",
      "pre:mcp-health-check"
    ],
    "PostToolUse": [
      "post:bash:command-log-audit",
      "post:quality-gate",
      "post:edit:accumulate"
    ],
    "Stop": [
      "stop:format-typecheck",
      "stop:check-console-log",
      "stop:session-end",
      "stop:evaluate-session",
      "stop:cost-tracker"
    ],
    "ConfigChange": [
      "감사 로그 → .claude/audit.jsonl"
    ]
  }
}
```

**핵심 훅 설명**:
- `pre:bash:block-no-verify`: git 훅 우회(`--no-verify`) 차단 → 감사 추적성 보장
- `pre:insaits:security`: AI 보안 스캔 (AgentShield 102개 규칙)
- `post:bash:command-log-audit`: 모든 Bash 명령 감사 로그 기록 (CSAP D-06)
- `post:quality-gate`: 파일 변경 후 CSAP 준수 자동 검사
- `stop:evaluate-session`: 세션 종료 시 패턴 추출 → 공공 SaaS 스킬로 자동화

### A.5 품질 게이트 (7단계 — Q-Gate)

| 단계 | 게이트 ID | 검사 내용 | ECC 컴포넌트 | 담당 에이전트 | 통과 기준 |
|------|---------|---------|------------|------------|---------|
| G1 | Q-GATE-01 | 요구사항 검증 (FR ID 전수, 누락 없음) | `doc-updater` | Auditor | FR ID 0개 누락 |
| G2 | Q-GATE-02 | 설계 완전성 (섹션, 다이어그램) | `planner` | Auditor | Design 문서 섹션 100% |
| G3 | Q-GATE-03 | 코드 품질 + 보안 | AgentShield 102규칙 | Reviewer | CRITICAL 0개 |
| G4 | Q-GATE-04 | 테스트 커버리지 | `e2e-runner` | Tester | 신규 80%+, 변경 90%+ |
| G5 | Q-GATE-05 | OWASP Top10 통과 | `security-reviewer` | Reviewer | HIGH 이상 0개 |
| G6 | Q-GATE-06 | CSAP 해당 Phase 준수 100% | healthcare-reviewer 확장 | Auditor | 해당 Phase 항목 0개 미충족 |
| G7 | Q-GATE-07 | 감사 추적 완비 | `command-log-audit` | Auditor | `audit.jsonl` 기록 완비 |

모든 게이트는 각 PDCA Phase 완료 전에 순서대로 통과해야 합니다.
통과 기준 미달 시 해당 에이전트가 자동으로 재작업을 요청합니다.

### A.7 Continuous Learning 구성

ECC의 세션 기반 학습 시스템을 공공 SaaS 도메인에 적용합니다.

| 학습 대상 | 추출 방법 | 저장 위치 | 적용 시점 |
|---------|---------|---------|---------|
| CSAP 준수 패턴 | `stop:evaluate-session` | `~/.claude/skills/csap-patterns/` | 다음 세션 자동 로드 |
| 감리 산출물 패턴 | `stop:evaluate-session` | `~/.claude/skills/audit-patterns/` | 다음 세션 자동 로드 |
| k3s 구성 패턴 | `stop:evaluate-session` | `~/.claude/skills/k3s-patterns/` | 다음 세션 자동 로드 |
| Dead code 패턴 | `stop:cost-tracker` | `~/.claude/skills/refactor-patterns/` | Refactorer 에이전트 자동 사용 |

학습된 패턴이 누적될수록 반복 작업 비용이 감소하며,
CSAP 항목별 구현 방법이 스킬로 자동화되어 팀 전체가 공유합니다.
