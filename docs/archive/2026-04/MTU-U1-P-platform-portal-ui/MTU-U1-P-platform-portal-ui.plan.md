## Context Anchor

### WHY (왜 필요한가)

1. **MTU-U1 범위 한계**: 기존 MTU-U1은 디자인 토큰, 컴포넌트 표준, 접근성 가이드를 정의했지만 실제 포털 애플리케이션 페이지와 비즈니스 로직에 특화된 UI 컴포넌트는 포함하지 않음
2. **동적 서비스 메뉴 UX 미설계**: 비즈니스 서비스가 5개 → 50개로 증가할 때 테넌트 포털 메뉴가 단순 목록으로 붕괴하는 UX 문제 선제 해결 필요
3. **MTU-U1 Gap 미해결**: G-01(유기체 컴포넌트 미구현), G-02(템플릿 계층 미완성) 2건이 CONDITIONAL PASS 상태로 방치됨
4. **관리자/테넌트 포털 전용 컴포넌트 부재**: 테넌트 그리드, 빌링 대시보드, CRM 카드, 서비스 마켓플레이스 등 플랫폼 특화 컴포넌트가 없어 MTU-P16a~P17 구현 시 중복 개발 발생

### SCOPE (범위)

**In Scope**:
- 관리자 포털 공통 레이아웃 및 핵심 페이지 컴포넌트
- 테넌트 포털 서비스 허브 + 서비스 레일 스위처 컴포넌트
- 서비스 마켓플레이스 UI 컴포넌트 (카탈로그, 상세, 구독 위저드)
- 유기체(Organism) 컴포넌트 5종 (G-01 해결)
- 페이지 템플릿 3종 (G-02 해결)
- MTU-U1 보안 갭 SG-01/SG-02 수정 (이월 이슈 해결)
- 모바일 하단 탭바 네비게이션 컴포넌트

**Out of Scope**:
- 관리자/테넌트 포털 실제 페이지 구현 (→ MTU-P16a, P16b, P17)
- 백엔드 API 연동 (→ 각 서비스 MTU)
- 비즈니스 로직 특화 컴포넌트 (→ 각 테넌트 구현)
