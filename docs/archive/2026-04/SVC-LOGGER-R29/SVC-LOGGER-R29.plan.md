## Executive Summary

## Context Anchor

| 항목 | 내용 |
|------|------|
| WHY | 17개 마이크로서비스에 통일 로그 형식 필요. CSAP D-06 필수 |
| WHO | 개발자 (디버깅), SRE (장애 분석), 감사팀 (보안 감사) |
| RISK | 비구조화 로그 → 장애 분석 지연, 감사 준비 부적합 |
| SUCCESS | JSON 구조화, 레벨 제어, PII 마스킹, 자식 로거 지원 |
| SCOPE | In-process 로그 라이브러리 (외부 전송은 수집기 담당) |

## 기능 요구사항

| ID | 요구사항 | 우선순위 | 검증 방법 |
|----|---------|---------|----------|
| FR-LOG.1 | JSON 구조화 로그 출력 (timestamp, level, message, context) | P0 | 단위 테스트 |
| FR-LOG.2 | 로그 레벨 (debug, info, warn, error, fatal) | P0 | 단위 테스트 |
| FR-LOG.3 | 컨텍스트 바인딩 (서비스명, 테넌트ID, 요청ID 등) | P0 | 단위 테스트 |
| FR-LOG.4 | 자식 로거 (child logger, 컨텍스트 상속) | P1 | 단위 테스트 |
| FR-LOG.5 | PII 마스킹 (이메일, 전화번호, IP 주소) | P0 | 단위 테스트 |
| FR-LOG.6 | 성능 타이머 (경과 시간 측정) | P1 | 단위 테스트 |
